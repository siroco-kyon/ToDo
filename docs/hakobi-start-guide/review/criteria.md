# HAKOBI はじめ方ガイドの独立評価基準

対象読者は、紹介レポートを読んで使ってみたくなった、Web やサーバーの専門知識がない人とする。自分の PC でひとりで試し、個人データをチームへ引き継ぎ、必要に応じてチーム用サーバーを配置できるかを評価する。

評価対象は完成した HTML 全体、付属ファイル、ガイドが案内するアプリの実画面。執筆者の説明や意図による補完はしない。リポジトリの実装・コマンド・画面を根拠に、評価者が独立して採点する。目標は 90 点以上だが、達成のために配点や判定を後から変えない。

## 採点方法

各項目は 20 点、合計 100 点。各項目の四つの確認事項をそれぞれ 0〜5 点で採点する。

- 5 点: 実装・実画面と一致し、初心者が説明を補わず実行・判断できる。
- 4 点: 実行できるが、軽微な補足や表現の改善余地がある。
- 3 点: 大筋は正しいが、前提・操作・結果のいずれかを読者が推測する必要がある。
- 2 点: 説明が部分的で、初心者は途中で迷う、または復帰しづらい。
- 1 点: 言及だけで実行に足りない、または重要な誤解を招く。
- 0 点: 欠落、実装と矛盾、実行不能。

最終報告では各確認事項の点数、根拠となるガイドの節・画面・ソース、問題と修正案を記録する。実施できなかった確認は未検証と明示し、確認できた扱いにしない。

## 1. 仕様と実操作の正確性（20 点）

1. 個人用 Electron とチーム用 HTTP/WebSocket の関係、データ保存先、ブラウザとデスクトップの違いを正確に説明している。
2. ガントを中心に、タスク・依存関係（Finish to Start）・期限・進捗ログなどの用語と操作が現在の画面に一致している。
3. ダウンロード、ログイン、管理者、同期、ビルド、公開などの説明・URL・コマンドが実装と一致している。
4. 手順の到達結果と制限を正確に示し、自動移行・自動更新・アクセス制限など存在しない動作を約束していない。

## 2. 自分の PC でひとりで始められること（20 点）

1. 読者が入口を選べる。インストーラーの入手方法、必要な環境、初回起動までの手順が具体的である。
2. 個人用を選んでから、最初のタスクを登録し、ガントで確認するまでを、実画面のラベルに沿って進められる。
3. 日程・依存関係・進捗などを小さな例で試せ、何が変われば成功か自分で確かめられる。
4. データ保存・バックアップ・再開方法が分かり、代表的な失敗時にも次に取る操作を選べる。

## 3. 個人データからチームへの移行を理解できること（20 点）

1. 「接続先を切り替えること」と「個人データを移すこと」を区別し、移行を行う人・時点・対象を明示している。
2. 移行前のバックアップ、対象ファイル、必要な権限、実行場所、実行コマンド・操作を、実装に沿って説明している。
3. 担当者・ユーザーなどの扱い、移行先データとの関係、重複・上書きなど実装上の注意を誤解なく理解できる。
4. 移行後の確認方法と、失敗時の戻し方・やり直し方が分かり、元の個人データの扱いも説明している。

## 4. チームで使う意味と日々の使い方が伝わること（20 点）

1. 管理者・メンバーの役割と、アカウント発行から各自の接続・ログインまでの流れが具体的である。
2. 担当者割り当て、共有ガント、同期、チームダッシュボードの利点を、実際の共同作業の例で理解できる。
3. 進捗ログ・返信・通知などをどの場面で使うかが分かり、読む人と書く人それぞれが最初の操作を選べる。
4. ブラウザ利用とデスクトップ利用を自分の仕事に合わせて選べ、便利さと利用条件が誇張なく伝わる。

## 5. 初心者が設定を行い、直感的に読み進められること（20 点）

1. サーバー、LAN、URL、ポート、ビルドなど初出の用語を、その場で必要な範囲だけ説明している。
2. サーバーを置く PC、Node.js 等の準備、コマンド実行場所、依存の分離、ビルド・起動・接続確認まで順序立てて実行できる。
3. 起動中の PC・ネットワーク・ファイアウォール・管理者設定・データ保全など、社内 LAN 運用に必要な条件と困ったときの切り分けが分かる。
4. 目次・段階・画面例・注記・コード表示・画面幅への対応が読みやすく、現在地、次の操作、成功状態を迷わず見つけられる。

## 合計点に関係なく報告する重大な問題

- データ消失・破損・意図しない上書きや重複を招く手順。
- 移行が自動で完了するなど、個人データの行方を誤解させる説明。
- インターネットへの公開を社内 LAN と同じ前提で案内するなど、運用条件を外れた導入。
- 認証情報や管理者権限の誤った扱い、誤った保存先・接続先への誘導。
- 初心者向けの主経路が実行不能、または画面が存在せず途中で進めなくなる問題。

重大な問題は、点数だけで合格扱いにしない。根拠と影響を明記し、修正後に該当経路を再確認する。

## 初心者役の定性質問

評価者はガイドを初めて開いた想定で、次の質問にガイドだけから答えられるか確認する。答えにくい箇所には、迷った理由と期待する説明を残す。

1. まず何をダウンロードし、どのボタンを押せば、自分ひとりで始められますか。
2. サーバーを先に用意しなくても試せますか。私のデータはどこに残りますか。
3. 最初のタスクを作れたことを、どの画面の何で確認できますか。
4. 前の作業が終わってから次の作業を始めたいとき、どう設定すればよいですか。
5. 作業の目的、今の状況、日付を残す報告は、それぞれどこに書きますか。
6. 同僚と使いたくなったとき、誰に何を用意してもらいますか。
7. チームに接続すると、ひとりで作ったタスクもそのまま見えますか。移す作業は誰がしますか。
8. 移す前に何を保存し、移した後はどのタスク・担当者を確認しますか。
9. 移行に失敗したり二度実行したりすると、何が起きますか。どう戻せますか。
10. チームのタスクを受け取り、進捗を伝え、ほかの人の報告を読む一日の流れを説明できますか。
11. ブラウザで使う場合とデスクトップ版で使う場合、どちらを選びますか。その理由をガイドから説明できますか。
12. サーバーを置く PC はどれですか。自分の PC と別の PC では、どの URL を開きますか。
13. コマンドはどのアプリを開き、どのフォルダで実行しますか。正常に動いた表示はどれですか。
14. その PC を終了したらチームはどうなりますか。翌日は何を起動しますか。
15. 「接続できない」とき、何から順番に確認し、誰にどの情報を伝えますか。
16. 読んでいる途中で、現在地と次の操作をすぐに見つけられますか。小さい画面でも同じですか。

## 完成後の評価記録

完成後に別ファイルへ、採点表、未検証事項、重大な問題、初心者役の回答と迷い、実画面の確認結果を記録する。現時点では基準のみであり、ガイドの評価・点数は付けていない。
