## 実装照合と検証結果

### インポート

server/src/import/import-desktop-db.ts は読取専用の個人DBを読み、指定ユーザーを各担当・投稿者等に設定して追加する。カテゴリは名前で再利用し、集計外フラグの相違を報告する。Settings、RunningState、外部の画像ファイルをコピーする処理はない。既存行を INSERT OR IGNORE で維持し、ドライランでは ROLLBACK。02の説明と一致する。

DesktopImportModal.tsx と SettingsModal.tsx で、「デスクトップDBを取り込む」「取り込み先メンバー」「ドライラン（確認のみ）」「取り込みを実行」、バックアップ欄を照合した。

独立して `npm.cmd --prefix server run test:auth-import` を実行し、8テスト成功。進捗ログ、入れ子返信、リアクション、履歴、カテゴリフラグ、古いDB等の取り込みが既存テストで確認できた。これはガイドを見た人のファイル選択操作や本番DB移行を実施した結果ではない。

### ビルド・配置・サービス

ルート package.json、server/package.json、electron-builder.yml、vite.web.config.ts、server/src/config.ts、server/service/install.cjs と config.cjs を照合した。

- `npm install` の Electron 再ビルドと、`npm --prefix server install` の独立依存は説明どおり。
- `npm run dist` の exe 命名、`build:web` の dist-web、`start:server` の配信経路が一致。
- 別PC配置の server + dist-web + ルートpackage.json は、ルート依存なしで起動できる構成。既定DBは server/data。
- Node 22.12以上の要件はロックファイルの依存のenginesで裏付けられる。既存の起動ガイドのv20表記との差も本文に明示される。
- `TodoTeamServer` と初回手動起動→停止→サービス化の順序は実装と一致。サービス登録時に開始イベントで起動する。
- バックアップ既定14世代、Web配信先とデスクトップ配布先の区別、publish:desktop による配布も一致。

独立して `node tests/server-deployment.cjs` を実行し、文書どおりのserver + dist-web配置がデスクトップソースなしで読み込める試験が成功。`node tests/service-config.cjs` も成功。実際のWindowsサービスはインストールしていない。

## 改善点（優先順）

1. **最初の一連の操作をもう一段具体化する。** 01に、ランチャーの個人用選択、タスク追加の入口、追加フォーム、詳細の進捗率と投稿欄を、押す場所が分かる小さな画面例で示す。今のガント画像は完成状態が分かるが最初のクリックを案内しない。
2. **依存関係を1回実際に追加できる説明にする。** 現状の「ガントやタスク詳細から編集」だけでは、初心者は欄やボタンを探す。片方の方法だけでも、先行タスクを選ぶ→待機日数を決める→追加→日付を確認する操作を示すとよい。
3. **設定の入口と取り込み画面を示す。** データ保存場所、ユーザー管理、取り込み、バックアップで「設定」を繰り返し使う。初出に位置を示す画像と、取り込み画面の選択項目・ドライラン結果の例があると迷いが減る。
4. **同梱運用資料への導線を明確にする。** 「同封の運用ガイド」「起動ガイド」の正式なZIP内ファイル名を併記すると、どれを開けばよいか即断できる。単体HTMLで読む場合のGitHub参照先も該当段落の近くにあると復元や更新時に探さずに済む。
5. **Node.jsとネイティブビルドの準備に短い選び方を補う。** 22系Windows x64の入手時に選ぶ項目、Python・C++の準備が必要な場合の所要負担を少し具体化すると、自分で行うか準備担当者へ依頼するか判断しやすい。外部手順の丸写しは不要。

## 実画面・可読性

通常PC画面では、落ち着いた色、本文と見出しの差、番号付き手順、到達状態の緑枠、詳細の折り畳み、コマンドの区別が有効。全20スクロールにわたり大きな崩れ・本文の切れ・重なりを認めない。画像は架空データと明記され、個人用との違いもキャプションで説明される。

進捗ログと定例の画面例は本文の相談→決定と一致。通常表示では画像内文字が本文より小さいが、HTMLに拡大ダイアログがあり、ブラウザ検査記録にもzoom成功がある。ガント図がチームデータなので、個人用で最初に見る画面との対応には説明補助が望ましい。

通信SVGは文字を含む箱全体を動かしていない。静止キャプチャから動作の滑らかさを検証済みとは言えない。ソース上の周期と端点一致、停止用CSS/SMIL制御、prefers-reduced-motion対応を確認した。GIFの動作確認は生成担当側で別途実施中と聞いており、ここでは未検証。

## 未検証・限界

- 新規Windows PCへのNode.js・Visual Studio・Python導入、クリーン環境でのnpm install、インストーラー生成と実インストール。
- 実際のWindowsサービス登録、再起動後の自動起動、権限・会社ポリシーによる差。
- 別の物理PCからのLAN接続とファイアウォール設定。
- 実ユーザーの個人DB取り込み・本番のバックアップ復元。
- 狭いPC幅とPC拡大表示の専用実測。CSSの1000px以下の切替は確認したが、読了と操作の実測で代用していない。
- 本評価者によるブラウザの各ボタン再操作と通信SVGの動画再生検証。執筆側の検査JSON、静止画像、実装確認を区別している。

これらを未検証とするために、スマホ対応の有無など依頼外の基準で点数を増減していない。追加のPC幅・拡大表示確認後も、この初稿の記録は保存し、改訂評価を別に残す。
