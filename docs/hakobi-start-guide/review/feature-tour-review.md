## 指摘した2点と解消確認

### 1. 計画で「今日に入れる」と時間配置を分ける

本文の「まずは仕事を1件『今日に入れる』で置き、自分の一日のどこで取り組むか決めて」は、時間割へ置く操作まで済むようにも読める。

実装の PlanView.tsx では「今日に入れる」は**時刻未定で追加**する操作。「時間に置く」を押して時間割の空き時間を選ぶか、ドラッグで配置する。画像内にもその区別が明記されている（PlanView.tsx の674〜706、1785、1846行付近）。追加してから「時間に置く」で時間帯を選ぶという2段階が本文にあると正確。

15分単位の調整は SNAP_MINUTES=15、MIN_DURATION=15、±15分の操作と一致。前日の未完了の繰り越しも実装にある。画像の午前と午後の予定・2時間15分は撮影データの60+30+45分と対応する。

### 2. 返信・要相談をチーム専用機能のように扱わない

ツアー末尾の「ガントの担当者、メンバー別の状況、進捗ログへの返信・要相談・@名前、リアルタイムの共有が加わります」は、返信と要相談そのものが個人用にはないと受け取られ得る。

個人用にも progressNoteSetNeedsDiscussion / progressNoteCommentCreate のIPCがあり（src/preload/index.ts:228、243付近）、TodoDetailの共通UIも要相談を切り替えられる（1515行付近）。チームでは、これらを**ほかの人との相談に使える**という用途を示すと誤解がない。担当の割り当て、メンバー状況、相手を指定する通知、サーバーを通じた共有はチームの説明でよい。

**解消確認:** 最終本文は「『今日に入れる』で追加し、『時間に置く』から時間帯を選ぶ」と2段階を明記。チームの説明も「担当者やメンバー別の状況を共有し、進捗ログへの返信や『要相談』を使って、ほかの人と相談できます」に変更され、機能自体がチーム専用との誤解を解消した。再生成されたreading-04.pngとreading-06.pngでも同じ文面を確認。どちらも解消済みであり、残存する指摘ではない。

## 「どの画面で何をするか直感的か」

**おおむね直感的。** ガント=日程、計画=今日の時間帯、カンバン=状態、タイマー=計測、記録=計測結果、ToDo=小さな確認、報告=出力という役割を、見出しと画像で区別できる。依存関係をガントと別カードで取り上げたことで、単なる並び順ではないことも伝わる。

2列カードの計画・カンバン・ToDoは、通常表示では細かい文字が小さい。クリック拡大の明示と元画像の解像度は十分。計画の「まず押す所」は最終本文で正確になった。タイマーの切り出しは計測中なので、本文の「計測開始」ボタン自体は見えない。開始前の位置が分かる図は将来の改善余地。
