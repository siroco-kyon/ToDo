HAKOBI はじめ方ガイド
まずは、ひとりで。育てた仕事を、チームへ。
いま進めている仕事をひとつ、HAKOBIに登録してみませんか。自分のPCで予定と進捗を確かめ、チームで使うときは、そのデータを取り込んで相談や分担につなげられます。できることを画面で見るひとりで始める準備を担当する方へHTMLを開くだけで読めます
01
自分の仕事を見える形に
個人用ならチームサーバーは不要。ガントで予定を並べ、作業の区切りに記録します。02
記録をチームへ引き継ぐ
管理者が個人用DBを取り込みます。作り直す前に、いまのタスクと記録を活かせます。03
同じ仕事を見ながら相談
担当と期限を共有し、困ったことはその仕事の進捗ログへ。返信や定例の対応も残せます。

いまの状況から、読む順番を選べますまずひとりで試したい社内に接続先がある新しくチームを用意する
インストーラーを入手 → 個人用で起動 → 仕事をひとつ登録。インストーラーがなければ、準備担当者へ依頼するか、04の手順で作れます。01 ひとりで始めるへ進む →

このガイドはWindows（x64）のPCと社内LANでの利用を案内します。社外からの接続やインターネットへの公開は、この手順の対象外です。初心者の方は、社内PCの管理ルールも確認しながら進めてください。

FEATURE TOUR / まずは画面で
予定を立てる、進める、振り返る
HAKOBIは仕事を一覧にするだけでなく、今日の予定、作業時間、相談、報告も同じタスクにつなげて使えます。まずは、自分の仕事で使ってみたい画面を見つけてください。
下の8つは個人用・チーム用で共通する機能です。担当者の表示や割り当て、みんなの状況を見る機能はチーム用で使えます。画像をクリックすると拡大できます。

日程を見渡す
ガントで、仕事の予定を並べる
「今週は何が重なっている？」「来週までにどこまで進める？」を、仕事の横棒と進捗率で確かめられます。日・週・月・年の表示を切り替え、日程はバーのドラッグでも調整できます。
見るところ：横棒の開始・期限、進捗率、赤枠の今日。架空のチーム画面なので担当名も表示されています。
まずは2つの仕事を登録して、同じ週に予定が重なっていないか見てみてください。
前後の順番
先に終える仕事と、その次をつなぐ
「資料を整えてから送る」のような順番は依存関係でつなげられます。先行タスクの日付を変えると、後続の日程も再計算されます。間を空けたいときは待機日数を設定できます。
「説明会の配布資料を整える」から「資料を参加者へ送る」へのつながり。Finish to Startの方式です。
確認用の仕事で順番をつなぎ、日付を動かすと後続がどう変わるか試せます。01に追加操作の手順があります。
今日の段取り
やる仕事を、時間帯に置く
ガントで見渡した仕事を、今日の「計画」に置いてみます。時間帯と見込み時間を決め、15分単位で調整できます。前日に終わらなかった仕事の繰り越しにも使えます。
配布資料の作業と説明会前の確認を、午前・午後に置いた架空の予定です。
まずは仕事を1件「今日に入れる」で追加し、「時間に置く」から時間帯を選んでみてください。
状態で整理
進行中と回答待ちを、分けて見る
「カンバン」は、未着手・進行中・保留中・完了の列に仕事を並べる画面です。カードをドラッグして状態を変えられます。回答待ちの仕事は保留にし、メモに理由や再開条件を残せます。
取り組んでいる仕事と、関係先からの回答待ちを分けて見られます。
保留は完了とは別の状態です。再開するときは進行中へ戻して使います。
作業時間を計測
取り組み始めたら、タイマーを押す
タスク詳細の「計測開始」で、その仕事の時間を測れます。停止すると作業ログに残るので、終わってから時間を思い出して書く代わりに使えます。
架空の作業を35分計測した状態のデモ。時間は撮影用データで、実際の作業実績ではありません。
まずは短い作業を始めるときに計測し、終わったら止めて「記録」を開いてみてください。
振り返り
作業した時間と内容を確かめる
「記録」では、計測した作業を振り返れます。予定に対して何に時間を使ったかを確かめ、次の予定を考える材料にできます。
資料を確認した作業の時間と記録。上のタイマーのデモを停止して保存した実画面です。
日々の進捗を文章で残すのが進捗ログ、計測した時間を残すのが作業ログです。用途に合わせて併用できます。
小さな確認をまとめる
ToDoリストを、チェックして進める
「会場を予約する」「人数を確認する」「資料を印刷する」。説明会の前に忘れたくない確認は、ToDoリストの中の項目としてまとめられます。済んだ項目にチェックを付けて使います。
会場の予約を済ませ、人数確認と資料の印刷を残した例です。
タスクの種類をToDoリストにして、確認項目を追加します。日程と進捗率で管理したい仕事とは、使い方を分けられます。
定例と週報の材料
日々の記録を、報告へ取り出す
「報告」で期間を選び、進捗ログやメモ、期限の変更などを見直せます。「Markdownをコピー」なら見出し付きの文章に、CSVなら表として扱うデータに取り出せます。必要な部分を選び、普段の報告先へ貼り付けて使います。
期間・担当の指定と出力ボタン。担当の選択はチーム用の画面例です。
チームでは「定例モード」から次の対応をタスクにすることもできます。03で相談から定例への流れを見る →
チームで使うと、ここから相談へ進めます
担当者やメンバー別の状況を共有し、進捗ログへの返信や「要相談」を使って、ほかの人と相談できます。「@名前」で相手を指定し、更新もリアルタイムで共有できます。機能を見て気になったら、03の共同作業の例へ。まず自分で試すなら、次の01へ進んでください。
画面は実際のアプリを専用の一時環境と架空データで撮影したものです。見せたい箇所を切り出しており、UIや数字を画像編集で描き直してはいません。

01 / YOUR OWN PC
今日の仕事を、ひとつ登録する
チーム利用を決める前に、個人用で使い心地を確かめられます。データは自分のPC内に保存され、個人用を選ぶとチームサーバーに接続せずに使えます。

Windows用インストーラーを入手する
配布担当者から HAKOBI-<バージョン>-setup.exe を受け取ります。社内ですでに配布中なら、サーバーURLの後ろに /download を付けたページから入手できます。
まだ入手先がない場合は、準備担当者にこのガイドを渡してください。自分で作る場合は04の「インストーラーを作る」へ進めます。ソースのZIPはそのまま実行できるアプリではありません。
受け取ったインストーラーから使う人は、Node.jsや開発ツールを入れる必要はありません。

インストールして個人用を選ぶ
exeを開いてインストールし、HAKOBIを起動します。最初の接続画面の下にある「このPCで個人用として使う」を押します。個人用のログインアカウントは不要です。すでに個人用を使っていたPCは、そのまま個人用で開くことがあります。
接続画面の下にある「このPCで個人用として使う」を選びます。サーバーURLの入力は不要です。ここまでできればOKサーバーURLを登録せずに、タスクの画面が開きます。

名前・開始日・期限を入れる
画面左上の「タスクを追加」を押し、たとえば「月次集計の見直し」と入力します。開始日を今日、期限を来週にして「追加」を押します。個人用ではチームメンバーの担当選択は出ません。
個人用の実画面。月次集計の見直しを10月22日から30日までの予定で登録し、進捗を25%にした例です。横棒で期間を確かめられます。

進めた分を記録し、もう一度開く
一覧のタスク名を押して詳細を開き、進捗率のバーを動かします。「進捗ログを書く」で短い記録を入力し、「投稿」を押します。「説明」は仕事の目的、「メモ」は今の状況を上書きする欄、「進捗ログ」は日付付きで積み重ねる記録です。アプリを閉じてもう一度開き、登録した仕事と記録が残っていれば、最初の確認は完了です。

設定は画面右上の名前（個人用は「メニュー」）を押し、「設定」から開きます。狭いPC画面では名前の代わりに歯車が表示されることがあります。
前の仕事が終わってから始める予定もつなげられます
「集計項目を確認する」の後に「入力フォームを試作する」を置く例なら、先行する仕事が終わってから後続の仕事を始める依存関係を設定できます。ガントやタスク詳細から編集します。方式はFinish to Startです。先行タスクの日付を変更すると、後続の日付も再計算されます。
試すときは確認用のタスクを2つ作ります。後続にしたいタスクの詳細で「依存関係」を開き、「先行タスクを追加」、相手のタスク、待機日数を選んで「追加」を押します。先行のタスクの日付を変え、後続も動くか確かめてください。実際の予定を変える前に、依存先も確認しましょう。

個人データの保存場所とバックアップ
設定の「データ」を開き、「データ保存場所」の「現在の場所」を確認します。そのフォルダに todo.db があります。保存場所を変えている場合も、この表示を基準にします。
バックアップするときはタイマーを止め、トレイの終了操作も使ってHAKOBIを完全に終了し、保存フォルダを別の場所へ丸ごとコピーしてください。起動中の todo.db だけをコピーする方法は避けます。復元が必要になったら現在のフォルダも退避し、終了中にバックアップ一式を戻します。

02 / BRING YOUR WORK
ひとりで始めた仕事を、チームへ
チーム環境が用意できたら、管理者が個人用のデータを取り込みます。元のPCのデータは残るので、まずバックアップしてから、取り込んだ内容を確かめられます。

図は横にスクロールして読めます。個人データをチームへコピーする手順個人用DBを完全終了後にコピーし、管理者が取り込み先メンバーを指定して確認と実行を行います。その後はチーム接続で利用します。個人用DBとの自動同期ではありません。自分のPC個人用の todo.db終了してコピーを渡す管理者が取り込むメンバー指定 → 確認 → 実行一方向のコピーチームサーバーチームのDBに追加以後はチーム接続で更新接続先を切り替えるだけでは、個人データは移りません。

管理者が受け取り先を用意する
先に04でチームサーバーを起動し、管理者が設定の「チーム管理」→「ユーザー管理を開く」で、取り込み先のメンバーを作ります。既存チームへ追加するときは、設定の「チーム管理」→「バックアップ」から現在のチームDBも保存します。

個人用を終了して、コピーを渡す
個人用の設定「データ」→「データ保存場所」でフォルダを確認します。タイマーを止めてHAKOBIを完全に終了し、フォルダ全体をバックアップします。その中の todo.db のコピーを、社内で認められた方法で管理者へ渡します。元のデータは消しません。

画面で件数を確認してから取り込む
チームに管理者でログインした画面で、設定 →「チーム管理」→「デスクトップDBを取り込む」を開きます。コピーした todo.db と「取り込み先メンバー」を選び、「ドライラン（確認のみ）」を押します。ドライランは件数を調べるだけで、まだ保存しません。
対象と件数を確認し、問題なければ「取り込みを実行」を押します。スキップや同名カテゴリの注意が出たら、内容を確認してから進めてください。

取り込み先で確認し、チーム接続に切り替える
取り込み先メンバーでログインし、仕事の名前・期限・進捗・ログを確かめます。担当の絞り込みやカテゴリの選択で見えなくなっていないかも確認します。
ブラウザならチームURLへ、デスクトップ版ならトレイの「チーム接続 / 個人用モード」から接続先の設定へ進みます。グループ名とサーバーURLを登録し、管理者が発行したアカウントでログインします。グループ名はそのPCで接続先を見分けるための名前です。ここまでできればOKブラウザとチーム接続中のデスクトップ版で同じ仕事が見え、変更が反映されます。以後の更新はこちらのチーム環境で行います。
何を引き継ぎ、何が変わるか
対象取り込み後
タスク・サブタスク・依存関係・作業ログ・予定チームDBに追加します。担当や記録のユーザーは指定したメンバーになります。
進捗ログ・返信・リアクション・変更履歴記録を引き継ぎ、投稿者・操作した人は指定したメンバーになります。
カテゴリ同じ名前は既存カテゴリを使います。「集計外」の設定が違う場合は、チーム側を維持し、注意を表示します。集計外は閲覧制限ではありません。
アプリ設定・実行中のタイマー取り込みません。個人用のカスタムアイコン画像もDB取り込みの手順で移す対象に含めません。
同じデータを再度取り込む場合同じIDの登録済みデータはそのままで、二重追加しません。個人用で後から編集した内容を、継続して同期する用途には使えません。

うまく取り込めなかったとき
ドライランだけならチームDBは変わりません。コピー元のアプリが完全に終了していたか、ファイルと取り込み先メンバーが正しいかを確認します。取り込み先メンバーを変えても、すでに取り込んだ同じIDのデータの担当は変更されません。
実行後に取り消したい場合、画面に取り込み専用の「元に戻す」はありません。元の個人用は残っているので、そこでの確認は続けられます。チームを取り込み前へ戻す場合は、管理者がサーバーを停止し、直前のバックアップから復元します。バックアップ以後のほかの人の変更も戻るため、利用者と調整してから05の復元手順を使ってください。

03 / WORK TOGETHER
予定を見るところから、相談するところまで
同じ仕事を見ながら話せると、「どの件の話？」から説明し直す手間を減らせます。担当を決め、困っていることを残し、次の定例で対応を決めるところまで試してみてください。

朝：担当状況を見る作業中：仕事の相談定例：次の対応へ

朝の確認を、同じ画面で
ガントでは仕事ごとの日程と担当を、「チーム」ではメンバーごとの未完了・保留・期限超過などを見られます。気になる仕事は件数だけで判断せず、進捗ログを読んで状況を確かめます。
架空のチームの実画面。リーダーもメンバーも担当状況を確かめる材料にできます。

迷ったことを、その仕事に残す
タスク詳細の「進捗ログを書く」から状況を投稿し、判断や手助けがほしいときは「要相談」を付けます。「@高橋」のように相手を指定すると通知され、返信は元の投稿の下に残ります。
月次集計の項目をどこまでそろえるか相談し、定例で確認する返信が付いた例です。

決まった対応を、担当と期限のある仕事に
「報告」から「定例モード」を開き、相談を見ながら次の対応を決めます。「決まったことをタスクにする」から追加し、「議事録をコピー」で記録を取り出します。週報の材料も「報告」の「Markdownをコピー」から取り出せます。
同じ定例の実画面から、担当・保存済みタスク・追加欄・メモを抜き出した例です。
メンバー
URLを開いて始める
管理者からチームURL・ユーザー名・初期パスワードを受け取り、ブラウザでログインします。自分でアカウントを作る方式ではありません。ログイン後は設定でパスワードを変更してください。デスクトップ版も選べます
作業中の記録を手元から
同じURLにチーム接続すると、ブラウザと同じ仕事を使えます。タイマー、トレイ、OS通知などの端末機能も使えます。サーバーへ接続できる環境が必要です。

最初の定例で「どのタイミングで進捗ログを書くか」「誰が相談を確認するか」「相談済みの印と議事録をどう残すか」も話し合うと、既存の報告との二重入力を避ける使い方を決めやすくなります。

04 / SET UP ON WINDOWS
準備する人のための、ビルドと配置
ビルドは、ソースコードから配布用のアプリや画面を作ることです。使うメンバー全員が行う作業ではありません。ここでは、Windowsの準備担当PCで作る方法と、社内LANで動かすサーバーPCへ置く方法を案内します。

インストーラーだけ作りたい
共通準備のあと、A：デスクトップ版へ。作ったexeを受け取る人は、開発環境なしで個人用を始められます。
チームでブラウザ利用したい
共通準備のあと、B：チームサーバーへ。WindowsのサーバーPCでビルドする方法を基本にします。

共通準備：Node.jsとソースを用意する
準備するPCに公式Node.jsの22系・22.12以上を入れます。バージョンはv22系、OSはWindows、構成はx64を選び、Windows Installer（.msi）を入手します。現在のビルド用依存が22.12以上を要求するためです。すでに別の版を使うPCでは、管理担当者と相談して用意してください。Node.jsの保守期間も確認できます。
HAKOBIのリポジトリを開き、「Code」→「Download ZIP」でソースを入手します。ZIPを展開し、package.json と server が並ぶフォルダを用意します。以下の例は C:\HAKOBI\ToDo です。ZIPの中のもう一段深いフォルダにならないよう確認します。
そのフォルダをエクスプローラーで開き、アドレスバーに powershell と入力してEnterを押します。コマンドは表示された画面にひとつずつ貼り付けてEnterで実行します。終わって次の入力欄に戻るまで待ちます。
インストール中に gyp・Python・Visual Studioのエラーが出る場合は、ネイティブ部品のビルド環境が必要です。Electron公式の案内に沿い、PythonとVisual Studioの「C++によるデスクトップ開発」を用意してから再実行します。ソフトの追加権限がないPCでは管理担当者に依頼してください。

Set-Location -LiteralPath 'C:\HAKOBI\ToDo'

A：デスクトップ版のインストーラーを作る
準備担当者が、Windows PCで実行します。npm install は必要な部品を取得し、個人用DBの部品をElectron向けに組み立てます。サーバー用の部品とは別です。通常のPowerShell / ソースの一番上 / 初回コピー
Set-Location -LiteralPath 'C:\HAKOBI\ToDo'
npm install
npm run dist
できあがり：C:\HAKOBI\ToDo\dist の HAKOBI-<バージョン>-setup.exe がインストーラーです。自分で開くか、利用する人へ配布し、01の個人用の手順へ進みます。exeを作れたことと、インストール後に個人用を起動できることを別々に確かめてください。

B：チームサーバーを起動する
サーバーPCは、チームのデータを保存し、みんなへ画面を配るPCです。使う間は電源を入れ、スリープさせず、メンバーと同じ社内LANにつないでおきます。LANは社内のPC同士がつながるネットワークです。
初めてなら、そのサーバーPCに共通準備のソースとNode.jsを用意し、そこでビルドする方法が分かりやすいです。サーバーPCの通常のPowerShell / ソースの一番上コピー
Set-Location -LiteralPath 'C:\HAKOBI\ToDo'
npm install
npm --prefix server install
npm run build:web
npm run start:server
npm --prefix server install はサーバー専用の部品を server\node_modules に用意します。ルートの node_modules をコピーして代用しないでください。build:web が dist-web を作り、start:server が画面とAPIを一緒に配信します。このPowerShellは開いたままにします。

サーバーPCでログインを確かめる
ブラウザで http://localhost:4577 を開きます。localhostは「いま操作しているPC」を意味します。ポートは通信の入口の番号で、このガイドの既定は4577です。
新規DBの管理者名は admin。初回起動ログに一度だけ出るランダムな初期パスワードを控えてログインし、設定でパスワードを変えます。既存DBなら、すでに作成した管理者でログインします。環境変数などで初期値を指定している場合は、その値を使います。

メンバー用のアカウントを作る
設定 →「チーム管理」→「ユーザー管理を開く」でメンバーを追加します。役割は通常メンバーを選び、必要な管理者だけ管理者にします。チームURLとユーザー名・初期パスワードを、社内の適切な方法で本人に伝えます。

別のPCから開く
サーバーPCで別のPowerShellを開き ipconfig を実行し、社内LANの接続にある「IPv4 アドレス」を調べ、上の入力欄へ入れます。メンバーのブラウザでは http://192.168.1.50:4577 を開きます。メンバーのPCでlocalhostを使うと、サーバーにはつながりません。
Windowsファイアウォールの確認が出たら、社内ルールで許可されたプライベートネットワークだけを対象にします。会社のポリシーで受信許可が必要な場合は、管理担当者へTCP 4577の社内LAN内からの接続許可を依頼します。ルーターのポート開放やインターネット公開は行いません。ここまでできればOK別のPCでログインでき、確認用タスクの変更がもう一方の画面にも反映されます。ここから02の取り込みか03の共同作業へ進めます。

ビルドするPCと、置くサーバーPCを分けたい
ビルドPCで npm run build:web を実行します。新規の配置先へ、リポジトリの server フォルダ、生成した dist-web フォルダ、ルートの package.json を、次のように配置します。server をコピーするときは、ビルドPCの node_modules、data、.env を持ち込まないでください。
配置先（例 C:\HAKOBI\ToDo）
  package.json
  dist-web\    ← ビルドした画面
  server\
    package.json / package-lock.json
    src\ / service\ / scripts\
サーバーPCにもNode.jsを入れ、配置先の一番上で npm --prefix server install、npm run start:server の順に実行します。画面がすでにできているので、ここではルートの依存インストールやWebビルドは不要です。新規配置のDBは server\data にできます。既存環境の更新ではこの新規配置のコピー手順をそのまま使わず、05の更新を参照してください。

デスクトップ版もサーバーから配布したい
同じPCでAとBを用意した場合、npm run dist でできたファイルを確認してから、ソースの一番上で npm run publish:desktop を実行します。検証済みのインストーラーと配布情報が dist-desktop に公開されます。単にexeを置くだけでは配布ページに出ません。
利用者には http://192.168.1.50:4577/download を案内します。新しい版の通知はありますが、自動インストールはしません。別PCで作ったインストーラーを配置する場合は、「HAKOBIのチーム接続と運用.md」の「デスクトップ版の配布と更新のお知らせ」にある3ファイルの配置手順を使います。

ログインや通信で出てくる言葉
URL
ブラウザのアドレス欄に入れる接続先です。チームではサーバーPCのURLを使います。
DB（データベース）
タスクや記録を保存するものです。HAKOBIでは主にtodo.dbというファイルを使います。
API

05 / KEEP IT RUNNING
続けて使うための、起動と保存
毎回の起動と停止
最初のビルドが済んでいれば、サーバーPCで配置先を開き、npm run start:server だけで起動できます。手動起動を止めるときは、そのPowerShellで Ctrl+C を押します。停止中やPCのスリープ中は、メンバーはチームへ接続できません。

PCの再起動後も自動で立ち上げたい（Windowsサービス）
最初は手動で動作確認し、初回管理者のパスワードも変更してから登録します。手動起動をCtrl+Cで止め、管理者として開いたPowerShellで次を実行します。サービスはウィンドウを開かずに常駐させるWindowsの仕組みです。サーバーPCの管理者PowerShellコピー
Set-Location -LiteralPath 'C:\HAKOBI\ToDo'
npm run service:install
Get-Service TodoTeamServer
既定のサービス名は TodoTeamServer。Runningなら、ブラウザでもログインを確認します。停止・再開は管理者PowerShellの Stop-Service TodoTeamServer / Start-Service TodoTeamServer で行います。サービスと手動サーバーを同じポートで同時に起動しないでください。独自名・複数チームの設定は運用ガイドを参照します。

バックアップを取る
チームの管理者は、設定 →「チーム管理」→「バックアップ」から現在のDBをダウンロードできます。既定のサーバー設定では1日1つの自動バックアップを14日分残します。同じPCだけでは故障に備えられないので、社内ルールに沿って別の保存先にも保管してください。
既定のDBは server\data\todo.db です。TODO_DATA_DIR を変更している場合は、その保存先を使います。更新前にはバックアップを取り、サーバーを停止してからプログラムを入れ替えます。

バックアップから戻す・更新する
戻す場合：メンバーへ停止を伝え、サーバーを停止します。現在のデータフォルダを別に退避し、戻したいバックアップDBを todo.db として配置します。古い -wal / -shm は混ぜません。「HAKOBIのチーム接続と運用.md」の「バックアップから戻す」に沿って再起動し、ログインとタスクを確認します。バックアップ後の変更は失われます。
更新する場合：新しいソースから画面を再ビルドし、停止中に server/src とWeb配信先（既定 dist-web）を更新します。server/data や独自のDB保存先、server/.env、配布済みの dist-desktop は残します。依存が変わった場合はサーバーPCで npm --prefix server install も行います。詳細な退避・配置・再起動は「Web版の立ち上げガイド.md」の更新手順を使います。
管理者パスワードが分からないときは、ほかの管理者に再設定を依頼してください。タスクを残す必要がある状態でDBを消して初期化しないでください。

WHEN YOU GET STUCK
つまずいた場所から、確かめる
コマンドが動かない・package.jsonが見つからない
Get-Location で場所を確認し、ソースの一番上へ移動します。Test-Path .\package.json がFalseならフォルダが違います。nodeやnpmが見つからないときは、Node.jsのインストール後にPowerShellを開き直してください。npm.ps1が拒否された場合はnpm.cmdを使えます。
npm installがエラーになる
先に node -v とネットワークを確認します。ネイティブ部品のエラーなら、04のPython・C++の準備を見直します。管理担当者へ相談するときは、実行したコマンド、フォルダ、Node.jsの版、エラー末尾を伝えてください。パスワードを含むログは渡さないでください。
EADDRINUSE / 4577が使用中と表示される
別のPowerShellで起動済みか、サービスが動いていないか確認します。すでに使っているサーバーを止めてよいか確認し、手動ならCtrl+C、サービスなら管理者の停止操作を使います。知らないプロセスを強制終了する手順ではありません。
自分のPCでは開くのに、メンバーのPCから開けない
サーバーPCのブラウザでlocalhost:4577が開くか確認。
サーバーPCの電源・スリープ・起動中のPowerShellまたはサービスを確認。
両方が同じ社内LANにいるか、IPv4と4577のURLが正しいか確認。
ファイアウォールのプライベートネットワーク許可を管理担当者に確認。
サーバーPCでは開くなら、アプリの再ビルドより先にネットワークを切り分けます。
チームに切り替えたら個人用の仕事が見えない
個人用とチームは保存先が別です。切り替えだけでは移らないので、02の取り込みを管理者に依頼します。個人用へ戻すと、元の個人データを使えます。取り込み済みなら、接続先・ログインユーザー・一覧の絞り込みも確認してください。
ダウンロードページに配布ファイルがない
配布担当者が npm run dist のあとに npm run publish:desktop を実行したか確認します。ブラウザで使うだけならインストーラーは不要なので、チームURLでログインできます。
