# HAKOBI 再確認と修正結果（2026年10月9日）

再確認で見つかった6件の不具合を修正しました。下書きの復元、時間表示の統一、ショートカット登録失敗の通知も追加しています。修正前の再現条件を自動テストに組み込み、実際のElectronでも確認しました。

## 修正後の動作

| 対象 | 対応 | 確認 |
| --- | --- | --- |
| B1：投稿先の取り違え | 専用イベントで対象を切り替え、タスクごとの下書きを復元。起動中の要求も保持 | 実ElectronでA→B→Aと文章の復元 |
| B2：送信中のままになる | 投稿中の解除と状態取得を分離。状態取得は10秒で打ち切り、古い要求と終了時の要求を中断 | 実Electronで15秒の投稿タイムアウト、応答しない状態取得、復旧後の再送 |
| B3：補助画面が空白になる | 失敗した画面を再表示時に作り直し、日本語の案内からも再試行可能 | 実Electronでタイマー・ガント・レポート・進捗窓のHTTP応答を切断し、復旧を確認 |
| B4：起動途中の停止から復旧できない | 停止した画面を破棄して接続中状態を解除。画面読込は30秒で打ち切る | 実Electronで最初の表示前にrendererを強制停止し、接続画面から再接続 |
| B5：Markdownコピーの失敗 | 共有コピー処理へ統一。権限拒否時は代替処理を使い、代替処理の失敗も表示 | 本番と同じ権限拒否設定の実Electronで、コピーされたMarkdownを確認 |
| B6：削除されたタスクの文章が消える | 投稿先を自動変更せず、本文とエラーを保持。削除済みタスクの下書きも一覧から開ける | 実Electronで削除後の400エラーを受け、本文・投稿先・保存内容が残ることを確認 |
| 下書きの回復 | クイック投稿に自分の下書き一覧・コピー・明示的な移し替えを追加。設定に旧版の進捗・コメント・返信の選択復元を追加 | 実Electronで本人確認後の復元。既存下書きの保護、他ユーザーの除外、保存失敗もテスト |
| 時間表示の統一 | メイン画面と右下タイマーをサーバー時刻に合わせ、トレイへ補正値を渡す。取得の合間は単調時計で進める | 端末時計の10分のずれを模擬した実Electron、時計変更・取得失敗・中断のテスト |
| ショートカット登録失敗 | 日本語で失敗を表示し、設定変更に失敗したら旧設定と登録へ戻す。起動時はほかの使えるキーを維持 | 登録失敗、復元、重複、無効化、起動時の部分的な競合をテスト |

送信結果が分からない下書きは、本文・投稿先・送信ID・停止するタイマーの開始時刻を保持します。結果が確認できるまで別タスクへの切り替えや文章の移し替えを止め、同じ内容を再送します。サーバーは同じ送信IDの投稿を重複させません。本文のコピーは可能です。

追加確認では、最初のログイン情報取得だけが応答しない場合にも読み込みが続くことが分かりました。認証確認を10秒で打ち切り、再試行・接続設定の画面へ進むように修正しています。実Electronで初回認証の停止と復旧後の再試行を確認しました。遅れて返った旧要求、画面終了、StrictModeの中断もテストしています。

下書き復元時のアカウント確認にも10秒の制限を設け、通信失敗のまま「復元中」になり続けることを防いでいます。

下書きは端末に保存した未投稿の文章です。旧版のWeb下書きは、保存したブラウザと接続URLで復元してください。ブラウザとElectronの保存領域は別なので、ブラウザの書きかけの文章をElectronへ自動移行する機能はありません。タスクや投稿済みの進捗は、従来どおりサーバーDBに保存します。

## 修正前の確認記録

以下は初回の再確認で残した記録です。上の対応表にある項目は修正済みです。

### 再現した不具合

優先度P1は投稿先の誤りにつながる問題、P2は特定の条件で操作や復旧ができなくなる問題です。

| ID | 優先度 | 問題 | 再現条件 |
| --- | --- | --- | --- |
| B1 | P1 | 進捗の投稿先が前のタスクに残る | Aの進捗窓を開いた後、Bを指定して同じ窓を開く |
| B2 | P2 | 通信失敗後も「送信中」のまま操作できない | 投稿がタイムアウトし、その後の状態取得も応答しない |
| B3 | P2 | タイマーの読込失敗後、復旧しても空白になる | タイマー画面のHTTP応答を切断し、復旧後に再表示する |
| B4 | P2 | 起動途中に画面が停止すると再接続できない | 接続確認成功後、最初の画面表示前にrendererが停止する |
| B5 | P2 | Markdownをクリップボードにコピーできない | localhostまたはHTTPSのチーム接続でコピーする |
| B6 | P2 | 削除されたタスクへの投稿失敗で、下書きとエラーが見えなくなる | 保存した送信内容を再試行し、タスク削除による400エラーを受ける |

#### B1：進捗窓を別タスクで開き直すと、前の投稿先が残る

タスクAの進捗窓で文章を入力した後、タスクBを指定して開き直すと、URLだけがBになります。タスクの選択欄と文章はAのままです。フォーカスによる再取得後も変わりません。利用者がBの進捗窓を開いたつもりで送信すると、Aに投稿する可能性があります。

ElectronはURLのhash変更を同じ文書内の移動として処理します。[既存窓の再利用](/D:/Github/ToDo/src/main/desktop-controller.ts:156)と、[初回だけ投稿先を初期化する処理](/D:/Github/ToDo/web/desktop/ProgressWindow.tsx:21)の組み合わせで起きます。

修正案は、専用のイベントまたはhash変更の検知で投稿先を切り替え、対象タスクの下書きを読み込むことです。送信中や送信結果が不明な場合は、保存した送信内容を保護して切り替えを保留します。A→B→Aの操作を、実Electronの回帰テストに追加することを推奨します。

#### B2：投稿のタイムアウト後も入力画面を操作できない

投稿には15秒の制限がありますが、その後の状態取得には制限がありません。[投稿処理](/D:/Github/ToDo/web/desktop/ProgressWindow.tsx:82)が状態取得の完了を待ち、最後に「送信中」を解除するため、状態取得が応答しない間は再試行・編集・画面内の閉じる操作が無効のままになります。

実際に15秒の投稿タイムアウトを起こし、その後の`/api/auth/me`を応答しない状態にしました。さらに17秒待っても、ボタンは「送信中」のままでした。投稿成功後も状態取得を待つため、同じ問題が起きる経路があります。

修正案は、[状態取得](/D:/Github/ToDo/web/desktop/useDesktopTask.ts:46)にも制限時間と中断処理を設けることです。送信中の解除は状態取得と分け、保存した同じ送信IDで再試行できるようにします。タイマー停止後の状態取得も同じ方針で見直すことを推奨します。

#### B3：タイマー画面が一度失敗すると、復旧後も空白になる

メイン画面が正常な状態でタイマー画面のHTTP応答だけを切断し、`ERR_EMPTY_RESPONSE`を発生させました。サーバ復旧後にタイマーを再表示しても、同じ窓が使われ、再取得されず空白のままになりました。

[画面読込の失敗処理](/D:/Github/ToDo/src/main/desktop-controller.ts:224)はメイン画面だけを扱い、[既存窓の再利用](/D:/Github/ToDo/src/main/desktop-controller.ts:153)はタイマーを再読込しません。

修正案は、補助ウィンドウの読込失敗や画面停止も管理し、再表示時に再読込または作り直すことです。タイマーで再現済みです。ガントとレポートにも同じ処理があるため、修正時には合わせて確認します。

#### B4：起動途中の画面停止で再接続できない

接続確認APIが正常に応答した後、トップページの応答を遅らせ、最初の画面表示前にrendererを強制停止させました。接続画面には再接続を促すメッセージが設定されましたが、「接続中」の状態が解除されません。接続画面に操作フォームが出ず、再接続処理も実行されませんでした。

原因は、[画面停止の処理](/D:/Github/ToDo/src/main/desktop-controller.ts:217)で接続中状態を解除せず、[再接続の入り口](/D:/Github/ToDo/src/main/desktop-controller.ts:98)が接続中の要求を受け付けないことです。

修正案は、停止した窓を破棄して接続中状態を解除することです。接続確認後の画面読込にも制限時間と中断操作を設けると、サーバの画面だけが応答しない場合にも復旧できます。

#### B5：チーム接続のMarkdownコピーが失敗する

localhostやHTTPS接続では`navigator.clipboard`が利用できますが、[Electron側](/D:/Github/ToDo/src/main/desktop-controller.ts:165)が書込み権限を拒否しています。[Markdownコピー処理](/D:/Github/ToDo/web/lib/client.ts:267)は拒否された場合の代替処理を行わず、エラーになります。本番と同じ権限設定を使った実Electronで、`Write permission denied`を再現しました。

設定画面のMarkdownコピーと`Ctrl+Alt+E`が対象です。ほかのレポートで使う共有ヘルパーには、権限拒否を捕捉する処理があります。

修正案は、[共有クリップボードヘルパー](/D:/Github/ToDo/src/renderer/src/lib/clipboard.ts:4)へ統一することです。現在のHTTP用代替処理はコピーの成否を確認しないため、失敗しても成功表示になる点も合わせて直します。回帰テストには本番の権限設定を使います。

#### B6：タスク削除による投稿エラーと下書きが見えなくなる

削除済みタスクへの送信内容を復元して再試行し、サーバから「タスクが見つかりません」の400エラーを受けました。その後、[タスクの自動選択](/D:/Github/ToDo/web/desktop/ProgressWindow.tsx:35)が投稿先を変更し、[下書きの読込](/D:/Github/ToDo/web/desktop/ProgressWindow.tsx:42)が文章とエラー表示を消しました。画面には空の入力欄と通常の案内が表示されます。

元の文章は削除されたタスクIDに対応する端末の保存領域に残っています。ただし、タスクが選択肢にないため、画面から復元できません。通常の書きかけの文章にも、別メンバーがタスクを削除・アーカイブした際に同じ自動選択処理が適用されます。通常の書きかけについてはコードで確認し、400エラー後の状態を実Electronで再現しました。

修正案は、文章がある間は投稿先を自動変更せず、タスクが利用できないことを表示することです。文章のコピーや別タスクへの明示的な移動を用意し、エラー表示も残します。

#### ショートカットの登録失敗を表示する

[ショートカット登録](/D:/Github/ToDo/src/main/desktop-controller.ts:300)が失敗しても、設定を保存し、ログに出すだけです。[設定画面](/D:/Github/ToDo/src/renderer/src/components/SettingsModal.tsx:249)は更新成功を表示します。OSや別アプリが使うキーを指定すると、使えない設定が残ります。

登録できた場合に設定を確定し、失敗したら元の設定へ戻して理由を表示する構成を推奨します。

#### 下書きの一覧と復元を用意する

今回、[タスク詳細](/D:/Github/ToDo/src/renderer/src/components/TodoDetail.tsx:121)と[進捗タイムライン](/D:/Github/ToDo/src/renderer/src/components/ProgressTimeline.tsx:186)の下書きをユーザー別にしました。従来のWeb版の下書きは旧形式の保存領域に残りますが、移行処理がないため更新後の画面には表示されません。個人用モードの保存形式は維持されています。

未投稿・送信結果未確認の文章を一覧で確認できる画面を推奨します。旧形式の下書きや削除されたタスクの文章も回復できるようにします。旧形式には所有者情報がないため、共有PCの文章を別ユーザーへ自動で取り込まない確認が必要です。

#### メイン画面・トレイ・ミニタイマーの時間を揃える

ミニタイマーは[サーバ時刻との差を補正](/D:/Github/ToDo/web/desktop/useDesktopTask.ts:71)しますが、[メイン画面](/D:/Github/ToDo/src/renderer/src/hooks/useTimer.ts:28)と[トレイ](/D:/Github/ToDo/src/main/desktop-controller.ts:320)はPCの時刻を使います。PCの時計がずれると、同じ作業で違う経過時間が表示されます。サーバに保存される作業時間はサーバの時刻で計算されます。

すべての表示で同じ補正値を使う構成を推奨します。
