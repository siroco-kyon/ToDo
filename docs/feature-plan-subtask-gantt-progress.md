## 1. 要望の整理と採用する仕様案

### 1-1. サブタスクの任意並べ替え

#### 要望

後から追加したサブタスクが末尾に固定されるため、作成後に上下へ移動して任意の順番へ変更したい。現在メインタスクで可能な並べ替えを、サブタスクでも使えるようにしたい。

#### 仕様案

- 並べ替え単位は **同じメインタスクに属するサブタスク内だけ** とする。別のメインタスクへの移動（親変更）は行わない。
- ガントの既存「並べ替えモード」で、メインタスクと同様にサブタスクのドラッグハンドルを表示する。
- タスク詳細でも上下ボタンを用意し、ドラッグ操作が難しい場合でも順番を変更できるようにする。
- 保存は操作ごとに即時実行し、失敗時は画面をサーバー／DBの順番へ戻してエラーを表示する。
- 保存順は `SubTasks.sort_order` に連番で記録する。既存列を使うため DB マイグレーションは不要。
- ガント内のサブタスク表示順は現在の「開始日優先」から `sort_order` 優先へ変更し、利用者が決めた順番が画面間で一致するようにする。
- 新規サブタスクは従来どおり末尾へ追加する。
- 完了状態、日付、担当者の違いで利用者の指定順を勝手に並べ直さない。

#### 受け入れ条件

- 3件以上のサブタスクを先頭・中央・末尾へ移動できる。
- 再読み込み、別画面への移動、アプリ再起動後も順番が維持される。
- タスク詳細とガントで同じ順番になる。
- Web版では別ブラウザにも順番変更が反映される。
- 別の親タスクのサブタスク順には影響しない。
- 空配列、重複ID、他の親のIDを含む不正リクエストは保存しない。

### 1-2. 表示期間外のタスク／サブタスクをガントに表示

#### 要望

現在の表示期間と交差しない項目がガントから消えるため、期限が過ぎても未完了のサブタスクなどを見落とす。期間外のメインタスクとサブタスクも表示対象にし、そのうえで完了／未完了を表示するか選べるようにしたい。

#### 仕様案

- 「表示期間」と「完了状態」を独立した表示条件として扱う。
- 表示設定に `期間外の項目を表示` を追加し、設定を既存の `localStorage` に保存する。
- この設定がオンなら、現在の期間と交差しないメインタスク／サブタスクも行として残す。
- 期間より前に終わっているバーは左端、期間より後に始まるバーは右端に **期間外マーカー** を表示する。選択中の期間自体は勝手に広げない。
- マーカーには「期間前」「期間後」と実際の開始日・期限をツールチップで示す。クリック時は既存の詳細表示へつなぐ。
- 既存の状態フィルター `未完了 / 完了 / すべて` は、メインタスクだけでなくサブタスクにも個別に適用する。
- 条件に合うサブタスクが1件でもある場合、親タスク行は階層を理解するためのコンテキストとして残す。親自身が状態条件外なら、親バーは控えめな表示にして「子項目のため表示中」と分かるようにする。
- `サブタスクを表示` がオフなら、サブタスクだけを理由に親タスクを追加表示しない。
- 日付未設定項目は、既存の `日付未設定を表示` の制御をそのまま使い、期間外設定とは混ぜない。
- アーカイブ済みタスクは従来どおり通常ガントの対象外とする。

#### 初期値案

- `期間外の項目を表示`: オン
- 状態フィルター: 現在保存されている値を維持

この組み合わせにより、普段 `未完了` を選んでいる利用者には、期限超過した未完了項目が自動的に残る。`完了` または `すべて` を選べば、期間外の完了項目も確認できる。

#### 受け入れ条件

- 表示期間より前に期限切れした未完了サブタスクが表示される。
- 状態を `完了` にすると期間外の完了項目だけ、`すべて` にすると両方が表示される。
- 期間外表示をオフにすると、現在と同じ期間交差フィルターへ戻る。
- 期間前・期間内・期間後・日付未設定の4種類が混在しても、行数と折りたたみが崩れない。
- 日／月／年スケール、手動期間、14日／30日／90日プリセットで同じ判定になる。
- 期間外バーが依存線やドラッグ操作の誤った座標計算を起こさない。

### 1-3. サブタスク期限に親タスク期限を追従

#### 要望

サブタスクの期限がメインタスクの期限より後になった場合、メインタスクの終了期限もそのサブタスク期限まで自動で延ばしたい。

#### 現状調査

- デスクトップ版 `src/main/db.ts` とサーバー版 `server/src/db/todos.ts` には、サブタスク作成／更新後に親期限を延ばす処理が既にある。
- ただしサブタスク更新の変更通知は `subtask` だけで、親タスク一覧を持つ `App.tsx` は `todo` 通知でしか再取得しない。そのためDBでは延びても、画面上の親期限が古いまま残る経路がある。
- 親期限を後から既存サブタスクより前へ短縮する操作では、期限関係を再検証していない。

#### 仕様案

- 常に `親タスク期限 >= その親に属する全サブタスク期限の最大値` を満たす。
- 親期限が未設定なら、期限を持つサブタスクの最大期限を親期限に設定する。
- サブタスクの作成、期限変更、ガントでの移動／リサイズ、タスク詳細での保存のすべてで同じ規則を通す。
- 親期限を直接短くする操作でも、サブタスク最大期限より前には保存しない。親期限をサブタスク最大期限へ補正し、利用者へ理由を通知する。
- サブタスク期限を前倒しした場合やサブタスクを削除した場合、親期限は **自動では短縮しない**。意図せず親計画を縮めないための一方向追従とする。
- 親期限が延びたときは既存の Finish-to-Start 依存関係連鎖を実行し、後続タスクも従来のルールどおり再計算する。
- サブタスク変更成功時は `subtask` と `todo` の両スコープを通知し、操作した画面と他クライアントの親表示を再取得する。
- サブタスク保存と親期限補正は可能な限り同一トランザクションにし、片方だけ保存される状態を避ける。

#### 受け入れ条件

- 親期限あり／なしの両方で、より遅いサブタスク期限へ即時追従する。
- 詳細画面とガントのどちらから変更しても同じ結果になる。
- Web版の操作端末と別端末の両方で、再起動なしに親期限が更新される。
- 親期限を短くしようとしても既存サブタスクより前にならない。
- サブタスク期限の前倒し／削除では親期限が自動短縮されない。
- 親期限延長により依存関係の後続日程が正しく連鎖する。

### 1-4. 進捗タイムラインの「いいねした人」と返信通知

#### 要望A: いいねした人をホバー表示

- 進捗投稿と各返信の両方で、いいねボタンへマウスを合わせると、いいねした利用者名を確認できるようにする。

#### 仕様案A

- `ProgressNoteReaction` にリアクションした人の一覧を追加する。各要素は利用者ID、表示名、色を持つ。
- DBには既にリアクションごとの `user_id` が保存されているため、スキーマ追加は行わず、取得クエリと返却型を拡張する。
- Web版は実ユーザー名を表示する。単一ユーザーのデスクトップ版は `自分` と表示する。
- いいねボタンのホバー／キーボードフォーカスで小さなツールチップを表示する。
- 0件ではツールチップを出さない。人数が多い場合も全員を確認できるよう、折り返しまたはスクロール可能にする。
- カウント、`reacted_by_me`、いいね解除、いいね時の通知という既存挙動は維持する。

#### 要望B: 「返信への返信」の通知

- 進捗投稿への直接返信だけでなく、ある返信に対する返信でも、返信先の投稿者へ通知する。

#### 仕様案B

- 通知対象は次の和集合とし、重複を除外する。
  1. 進捗投稿の作成者（既存挙動）
  2. 直接返信された親コメントの作成者（今回追加）
- 返信を書いた本人には通知しない。
- 投稿作成者と親コメント作成者が同一なら通知は1件だけ作る。
- 通知の `progress_comment_id` は新しく作成した返信IDにし、通知クリック時にその返信へ移動する既存導線を維持する。
- 親コメントが削除済み／別投稿のID／存在しないIDの場合は、コメント作成自体を既存どおり拒否し、通知だけが作られる状態を避ける。

#### 受け入れ条件

- 投稿と返信のいいねで、ホバー時に正しい利用者名が出る。
- 自分がいいねを追加・解除した直後も、人数と名前一覧が一致する。
- Aの投稿へBが返信するとAへ通知される。
- Bの返信へCが返信すると、AとBへ通知される。
- Bが自分の返信へ返信した場合、B本人には通知せず、Aへの既存通知だけが作られる。
- AがBの返信へ返信した場合、A本人には通知せず、Bへ通知される。
- 同一受信者への重複通知がない。
- 通知クリックで対象返信へフォーカスできる。

## 5. 既存機能を守るための注意点

- メインタスクの並べ替えはグローバル順、サブタスクは親内順であり、同じドラッグ状態を混用しない。
- 並べ替え中は既存どおり日付セル編集、バー移動、サブタスク追加を無効化する。
- 期間外マーカーは実日付を変更しない。描画座標だけを端へ固定する。
- 期間外項目を依存線計算へそのまま渡すと線が画面外へ伸びるため、線は期間内バー間だけ描くか、端点を明示的にクリップする。
- 親期限補正は一方向とし、サブタスク削除で親期限を勝手に縮めない。
- 親期限補正に `updateTodo` を再帰的に使う場合、依存連鎖や変更履歴が二重に走らない構造にする。
- Web版の通知はサーバー専用。デスクトップ版の通知APIが空実装である既存仕様は変えない。
- リアクション利用者名は画面表示用であり、通知や権限判定の根拠には使わない。
- `localStorage` の既存設定を読み込める後方互換を保ち、新設定がない場合だけ初期値を補う。

## 6. 実装前に確認したい方向性

以下を本プランの推奨案として置く。利用者から修正があれば、実装前に本ファイルへ反映する。

1. **期間外表示方法（推奨）**
   - 選択中の表示期間は変えず、期間前は左端、期間後は右端のマーカーで示す。
   - 代案は、期間外項目に合わせて時間軸自体を自動拡張する方法。ただし14日／30日表示の意味が崩れるため推奨しない。
2. **返信通知の対象（推奨）**
   - 投稿作成者と、直接返信されたコメント作成者の両方。本人除外・重複除外あり。
   - 代案は直接返信先だけだが、現在の投稿作成者への通知が失われるため推奨しない。
3. **サブタスク並べ替え画面（推奨）**
   - ガントのドラッグと、詳細画面の上下ボタンの両方。
   - 親をまたぐ移動は対象外。
4. **親期限の短縮（推奨）**
   - 子期限より前へは短縮させず、子の最大期限へ補正する。
   - 子の前倒しや削除時に親を自動短縮はしない。

## 8. 実装・検証結果（2026-08-27）

- サブタスク順序は、詳細画面の上下ボタンとガントの同一親内ドラッグの両方から変更できるようにした。不正なID集合はDB更新前に拒否する。
- ガントへ `期間外の項目を表示` を追加し、期間前／期間後を左右端のマーカーで表示する。完了状態は親と子へ個別に適用する。
- 親タスク期限がサブタスク最大期限より前にならない制約を、サブタスク変更、親の直接編集、依存関係による移動へ適用した。子の前倒しや削除では親を自動短縮しない。
- 進捗投稿と返信のリアクションへ利用者一覧を追加し、ホバー／キーボードフォーカスで表示する。入れ子返信では投稿者と直接の返信先へ、本人・重複を除外して通知する。
- 3ユーザーを使った一時DBのAPI検証で、並べ替え永続化、親期限延長と短縮防止、リアクション利用者名、直接返信／入れ子返信の通知受信者を確認した。
- Web画面の手動確認で、状態別サブタスク順、期間外マーカーのオン／オフ、いいね利用者名のアクセシブル表示、コンソールエラーなしを確認した。
- 次の静的検証と本番ビルドはすべて成功した。
  - `npx tsc --noEmit -p tsconfig.node.json`
  - `npx tsc --noEmit -p web/tsconfig.json`
  - `npx tsc --noEmit -p server/tsconfig.json`
  - `npm run build`
  - `npm run build:web`
- DBスキーマ、依存パッケージ、ロックファイルの変更はない。
