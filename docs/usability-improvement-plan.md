# ユーザビリティ改善 実装プラン

更新日: 2026-08-28

## 1. 対象範囲

複数視点レビューで提案した項目のうち、中長期として明示した以下は今回の対象外とする。

- 権限モデルの再設計
- 共同編集の競合検知
- 管理者向け横断操作履歴
- モバイル専用レイアウト
- 依存変更の影響プレビュー
- 共有・版管理された基準線
- 担当者キャパシティ／クリティカルパス

今回実装する項目は次のとおり。

1. 優先度ラベルの不整合修正（全画面で5が最高、1が最低）
2. 検索対象へメモ・サブタスク・担当者を追加
3. `個人／全体` と `プライベート` の誤解しやすい表示名称を整理
4. 親期限の自動延長結果を利用者へ通知
5. Toastの読み上げ、手動クローズ、エラー表示時間の改善
6. クイック追加、詳細編集、進捗投稿／返信の未保存保護・下書き保持
7. 読み込み失敗と空状態を区別し、再試行と次の操作を表示
8. 破壊的操作の確認を統一し、可能な操作にUndo／復元導線を追加
9. 適用中フィルター表示、全解除、保存ビュー
10. タスクの複数選択と一括編集
11. クイック追加の連続入力、複数行タスク／サブタスク追加、タスク複製・テンプレート
12. 既存の概要ダッシュボードをナビゲーションへ復帰
13. 今日以外の日付の計画、前日からの繰り越し、予定の±15分移動
14. 通知を未読／履歴として保持し、種類別ミュート、期限通知、タスク購読、@メンションを追加
15. ドラッグ操作のボタン／メニュー代替、モーダルのdialog属性・Esc・フォーカス復帰、色以外のラベルを補強

## 2. 実装原則

- Electron版とWeb版のAPI契約を常に対称に保つ。
- 既存DBは起動時マイグレーションで安全に拡張し、既存データを保持する。
- 破壊的操作は、対象と影響を明示してから実行する。
- 保存失敗時は入力内容を保持する。
- 新設定は既存利用者に安全な初期値を与え、localStorage旧形式も読み込めるようにする。
- 大きな機能はAPI／DB検証後にUIへ接続し、各フェーズで型チェックする。

## 3. フェーズ

### Phase 1: 不整合と発見性

- 優先度、検索対象、表示名称を修正する。
- 親期限補正の結果をAPI応答とUI通知で判別できるようにする。
- Toastと主要モーダルのアクセシビリティを改善する。
- 概要ダッシュボードを主要ビューへ復帰する。

### Phase 2: 入力・失敗・削除からの回復

- クイック追加と投稿系の下書きを保存する。
- 詳細編集の未保存離脱を確認する。
- 初期読込と詳細セクションへエラー／再試行表示を追加する。
- 空状態へ状況別CTAを追加する。
- 削除確認を統一し、タスクは既存アーカイブをゴミ箱として活用する。タスクとサブタスクには元の状態・位置へ戻すUndoを設け、返信を持つ進捗ログは誤復元を避けるため確認付き削除とする。

### Phase 3: 検索・一括操作・再利用

- フィルターチップ、全解除、保存ビューを追加する。
- 一覧の複数選択と一括更新を追加し、個別処理の成功・失敗を集計して失敗対象だけ選択に残す。
- 連続追加、複数行追加、サブタスク一括追加を追加する。
- タスク複製と名前付きテンプレートを追加する。

### Phase 4: 日別計画

- 任意日付をAppとPlanViewへ通す。
- 前日／翌日／日付選択と前日未完了の繰り越しを追加する。
- 予定を±15分、以降もまとめて移動できる既存APIをUIへ接続する。

### Phase 5: 通知

- 既読時に削除せず `read_at` を更新し、未読／すべてを切り替える。
- 利用者別通知設定、タスク購読、@メンションを追加する。
- Web版で期限超過／期限接近通知を重複なしで生成する。

### Phase 6: 回帰確認・文書・PR

- 型チェック、Electron/Web production buildを実行する。
- 一時DBを使ってマイグレーション、復元、一括操作、通知重複防止を検証する。
- ブラウザで主要導線、キーボード、狭いウィンドウ、エラー表示を確認する。
- READMEとサーバー更新手順を更新し、PR作成、チェック確認、マージを行う。

## 4. 受け入れ条件

- 既存データを持つDBをそのまま起動できる。
- Electron/Webの双方で主要機能に型エラーがない。
- 保存失敗や画面移動で入力内容が消えない。
- 削除・一括変更・日程変更の対象が利用者に明示される。
- 通知を既読にしても履歴から消えず、同じ期限通知が重複しない。
- フィルターや表示名称が実際の動作と一致する。
- 既存のガント、カンバン、計画、進捗、タイマー、リアルタイム同期が壊れていない。

## 6. 実装・検証結果

- 親期限の自動延長はサブタスク作成・更新APIの応答でも延長日を返し、詳細画面から結果を通知する。
- 複数行追加と一括操作は部分失敗を成功扱いにせず、成功件数を表示し、未処理の入力・選択を残す。
- 通知は未読を全件取得しつつ履歴を時系列表示する。期限通知の日付境界をISO時刻へ統一し、返信・メンション・購読の受信者をイベント単位で重複排除する。
- 任意日計画は要求世代、読み込み中、失敗・再試行を管理し、別日付の予定を誤操作しない。
- `npm run build:web`、`npm run build`、Electron/Web/ServerのTypeScript型チェックを実施する。
- 一時DBと実ブラウザで、複数行追加、メモ検索、フィルターチップ、一括追加、前日繰り越し、15分移動、概要、通知設定、タスク別下書き復元を確認する。
- 一時API利用者で、期限通知が再取得時も1件、メンションと購読の同一イベント通知が1件、親期限延長のAPI応答と保存値が一致することを確認する。
