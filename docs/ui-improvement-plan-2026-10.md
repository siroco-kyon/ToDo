## 3. ① サブタスクをマウスで並べ替える

### 現状
- タスク詳細: ▲▼ ボタンだけ（`TodoDetail.tsx` の `SubTaskOrderControls`）。1回押すごとに保存を待つ。5番目を先頭へ動かすのに4回押して4回待つ。
- ガント: ドラッグできるが、「並べ替え」ボタンでモードに入ったときだけ（`GanttView.tsx` の `isReorderMode`）。落とした位置の扱いが、上へ動かすと「前」、下へ動かすと「後ろ」になる。
- ToDoリストの項目（`TodoChecklist.tsx`）: ドラッグできる。落とした項目の「前」に入る。最後の項目の後ろには置けない。
- 保存は `subtaskReorder(todoId, orderedIds)`（両モードにある）。

### 変えること
1. 並べ替えの計算を共通の関数にする（`lib/` に置く。React 非依存）。落とす位置は、相手の行の上半分なら「前」、下半分なら「後ろ」。
2. タスク詳細（表示中・編集中の両方）: ▲▼ を「⠿」のつかみに替える。つかみをドラッグして好きな位置へ動かす。
   - 動かすのはつかみだけ（行の中に進捗バーのドラッグや入力欄があるため、行全体はドラッグさせない）。ドラッグ中の見た目は行全体にする。
   - 落とす位置に線を出す。離したときに1回だけ保存する。すぐ画面に反映し、失敗したら元の並びに戻して知らせる。
   - キーボード: つかみにフォーカスして Alt+↑ / Alt+↓ で1つずつ動かす。
3. ガント: 「並べ替え」モードに入らなくても、左の表のサブタスクの行のつかみで動かせるようにする。つかみは行にマウスを乗せたときに出し、タスク名の位置は動かさない。並べ替えモードは親タスクの並べ替え用に残す。同じ親の中だけで動かせる。
4. ToDoリストの項目も同じ計算（上半分は前・下半分は後ろ）と線の出し方にそろえる。最後の項目の後ろにも置けるようにする。

### 受け入れ条件
- 詳細で5番目のサブタスクを先頭へ、1回のドラッグで動かせる。保存は1回。
- 詳細で最後の項目の後ろへも置ける。落とす前に位置の線が見える。
- 保存に失敗すると元の並びに戻り、エラーが出る。
- Alt+↑↓ で動かせる。
- ガントで並べ替えモードに入らずにサブタスクを動かせる。バーのドラッグ（日程変更）や依存関係のつかみは今までどおり使える。
- ToDoリストで最後の項目の後ろへ置ける。
- サーバー版・デスクトップ版の両方で型チェックとビルドが通る。

### 今回やらないこと
- 別の親タスクへの移動（親を付け替える API がない）。
- 報告タブでの並べ替え。

## 4. ② ガントの表示面積を広げる

- 1280×720: ガント欄470px のうち左の表が453px で、時間軸がほぼ見えない。

### 変えること
1. 上部バー（`Toolbar.tsx`）を1段にする。カテゴリ／タスク一覧／今日の予定／アーカイブの切り替えは「表示」メニューへ。進捗レポート・設定・ログアウトはユーザー名のメニューへ（デスクトップ版はユーザーがいないので「メニュー」）。集計外の切り替えは「表示」メニューの中へ。
2. ガントを開いたとき、画面幅が 1600px 未満なら左の2つのパネルと右の「今日」を畳んだ状態で始める。ガントのパネルの開閉は、ほかの画面とは別に覚える。バーを押したときの詳細は今までどおり右に出す。
3. ガントの左の表は、既定で「タスク名」だけにする。開始・期限・進捗・担当は表示設定で出せる（バーの上にもタスク名・担当・進捗が出ている）。
4. ガントの見出しの2段（ボタンの段とチップの段）を1段の道具バーにする: 前へ・今日・次へ／日・週・月・年／ズーム／カテゴリ別・担当者別／遅れ・期限超過（押すとその行だけに絞る）／日付なし N件／1つ戻る・並べ替え・表示設定・別ウィンドウ。凡例は表示設定の中へ。
5. 表示範囲の外にある完了タスクは既定で出さない（着手時に今の既定値と動きを確認してから決める）。
   → 確認の結果、状態の絞り込みの既定は「未完了」で、完了したタスクはすでに隠れている。全員表示で空の行が多く見えたのは、完了した親タスクの未完了サブタスクの行と、今日から離れた期間のタスクの行だった。② では既定を変えない（8. に記録）。

### 受け入れ条件
- 1440px 幅で上部バーが1段（サーバー版・デスクトップ版とも）。1280px 幅でも1段。
- 1280×720 でガントを開くと、日表示で2週間分以上の時間軸が見える。
- 既存の表示設定（localStorage）を持っている人も、壊れずに開ける。

### 6-0. 並べ替えの不具合（② の Codex の指摘から見つけたもの）

- 現状: ガントの並べ替えモードとタスク一覧の手動並べ替えは、見えているタスクだけの並びで `todoReorder` を呼ぶ。両 DB は渡された ID に 0 から番号を振り直すので、絞り込み（担当: 自分 など）で隠れているタスクと番号が重なり、絞り込みを外すと並びが崩れる。
- 変えること: App の `handleReorder` で、見えている分の新しい並びを、全タスクの並び（`sort_order` 順）の中で見えている分が占めていた位置に入れ直してから保存する。隠れているタスクの位置は動かさない。計算は `lib/reorder.ts` に置いてテストする。② で入れた「遅れ・期限超過で絞り込んでいる間は並べ替えモードに入れない」制限は、この修正で要らなくなるので外す。
- 受け入れ条件: 絞り込み中に並べ替えても、隠れていたタスクどうしの順番と位置が変わらない。保存する ID は全タスク分。

### 6-1. ④ 詳細画面の作り直し

- 幅があるとき（詳細の欄が 880px 以上）は2列にする。左: 説明・メモ・サブタスク・進捗ログ。右: 状態などの欄・計測・進捗・依存関係・作業ログ・変更履歴。狭いとき（ガントの右のパネルなど）は今の1列のまま。
- 説明・メモは自動で保存する（入力が止まって1.5秒後と、欄から離れたとき）。「保存済み／保存中…／保存できませんでした（再試行）」を出す。保存ボタンはなくし、Ctrl+Enter ですぐ保存する動きは残す。保存に失敗しても入力は消さない。
- 変更履歴: このタスクの状態・期限・担当などの変更を、いつ（サーバー版は誰が）変えたかの一覧で出す。新しい順に20件、「もっと見る」で続き。1件のタスクの履歴を取る API（`todoChangeGetByTodo`）を両モードに足す。
- `tests/hakobi-detail-electron.cjs` の「説明を保存」「メモを保存」を押す手順を、新しい動きに合わせて直す。
- 受け入れ条件: 1440 幅の詳細画面で2列、ガントの右のパネルでは1列。説明・メモを打って手を止めると保存され、失敗したら入力が残り再試行できる。変更履歴が出る（デスクトップ版は変えた人の名前なし）。

### 6-2. ⑤ URL 連動と Ctrl+K

- 画面と開いているタスクを URL の検索部分に出す（例: `?view=gantt&task=<id>`）。画面を切り替えると履歴を積み、ブラウザの「戻る」「進む」で画面とタスクが戻る。その URL を開くと、その画面とタスクで始まる。ハッシュ（`#gantt-only` など）はほかの窓で使っているので使わない。
- タスク詳細に「リンクをコピー」を置く（サーバー版だけ。個人用のデスクトップ版はファイルの URL なので出さない）。
- Ctrl+K でコマンドパレットを開く: タスク名で探して開く、画面の切り替え、タスクを追加、パネルやアーカイブの表示の切り替え、設定を開く。↑↓・Enter・Esc で操作する。
- 受け入れ条件: Web 版で、画面を3つ切り替えてから「戻る」を押すと順に戻る。タスクの URL を新しいタブで開くとそのタスクの詳細が開く。Ctrl+K から主な操作ができる。デスクトップ版（個人用・チーム接続）でも起動と画面の切り替えが壊れない。

### 6-3. ⑥ 定例を早く終わらせる仕組み

- 報告タブに「定例モード」: 担当者を1人ずつ大きく表示する（その人のタスクのカード、要相談を先頭）。持ち時間のタイマー（既定3分、変えられる）、前の人／次の人、決まったことをその場でタスクにする（担当はその人）。終わったら議事録（Markdown）をコピーできる。
- 進捗ログの入力欄に「ひな形」（やったこと／次にやること／困っていること）と「予定どおり」（押すと「予定どおり進んでいます」を投稿）を置く。詳細・報告タブ・進捗タブの投稿欄で同じにする。
- 報告のリマインド（サーバー版）: 管理者が設定で定例の曜日を選ぶと、その前日の17時に、直近7日に進捗ログがない担当タスク（未完了・保留中を除く）を持つ人へ通知する（アプリ内の通知と、デスクトップ版の OS 通知）。通知の種類に「報告のリマインド」を足し、通知設定で止められる。Teams・メールには送らない。
- 受け入れ条件: 定例モードで人を切り替え、タスクを作り、議事録をコピーできる。ひな形と「予定どおり」が投稿欄で使える。リマインドが対象の人だけに1日1回届く（サーバーのテストで時刻を進めて確かめる）。

### 6-4. ⑧ 速さ

- 画面ごとに分けて読み込む（React.lazy: 報告・計画・進捗・概要・記録・チーム・ToDo・設定・進捗レポートなど）。
- 計測中の毎秒の描き直しを、時間を表示する部品だけにする（タイマーの秒を App の state から外す）。
- タスク一覧とガントの、画面の外の行の描画を省く（`content-visibility`）。ガントの行の仮想化は sticky と依存関係の線の計算に関わるので、測ってから決める。
- 受け入れ条件: 最初に読み込む JS が減る（変更前 755KB）。計測中に App が毎秒描き直されない。255件で一覧・ガントの操作が今より遅くならない。

### 6-5. ⑨ 管理者向け

- 自分でパスワードを変える（設定画面、サーバー版だけ）。サーバーの `/api/users/me/password` はすでにあるので、Api 契約にメソッドを足し、デスクトップ版は使えない旨のエラーを返す。
- バックアップ: 管理者が設定画面から今の DB のスナップショットをダウンロードできる。サーバーは毎日1回自動でバックアップを取り、決めた世代数（既定14）を残す。復元は画面からは行わず、手順を `docs/HAKOBI.md` に書く。
- 設定画面をタブで分ける（個人／チーム管理（管理者だけ）／データ）。デスクトップ版の配布状況のローカルパスと npm コマンドは「詳しく」に畳む。
- 接続状態: サーバー版で WebSocket が切れたら上部に「サーバーに再接続しています…」の帯を出し、戻ったら消す。
- 受け入れ条件: パスワードを変えて、新しいパスワードでログインできる。バックアップをダウンロードでき、開くとタスクが入っている。自動バックアップが世代数を超えたら古いものから消える。設定画面がタブで分かれる。サーバーを止めると帯が出て、起動し直すと消える。

### 6-6. ⑦ デザイントークンとライトテーマ

- 画面の部品に直書きしている色（133色）を、CSS 変数に置き換える。近い色はまとめ、役割（背景・面・境界・文字・弱い文字・強調・状態色など）が分かる名前にする。
- ライトテーマを、画面全体の色反転（`filter: invert`）から、変数の値の切り替えに変える。絵文字・担当者やカテゴリの色・画像が反転しなくなる。③ で入れたチェックボックスの打ち消しは要らなくなる。
- テーマに「OS の設定に合わせる」を足す。
- 進め方: 直書きの色を洗い出し、変数への対応表を作る → 機械的に置き換える → ライトの値を決め、主要画面をスクリーンショットで確かめる。ダークの見た目は変えない。
- 受け入れ条件: ライトテーマで主要画面（ガント・一覧・詳細・報告・進捗・計画・カンバン・設定）に読めない文字や反転した絵文字がない。ダークテーマの見た目が変わらない。
