# HAKOBI のチーム接続と運用

HAKOBI のデスクトップ版は、サーバーが配信する Web 画面を Electron のウィンドウに表示します。画面と API はサーバー側で更新し、タイマーやトレイなどの端末機能はデスクトップ版が担当します。タスクと進捗の保存先は既存のサーバー DB です。

## メンバーへの配布

1. サーバーで `npm run build:web` を実行し、`dist-web/` と更新した `server/` を配置します。
2. サーバーを起動し、同じ LAN の端末から `http://<サーバーIP>:4577` を開けることを確認します。
3. 管理者がメンバーのアカウントを発行します。
4. `npm run dist` でインストーラーを作り、`npm run publish:desktop` でサーバーへ公開します。メンバーには `http://<サーバー>:4577/download` を案内します。手順は[デスクトップ版の配布と更新のお知らせ](#デスクトップ版の配布と更新のお知らせ)にまとめています。
5. メンバーはダウンロードページからインストールします。HAKOBI の接続設定でグループ名とサーバー URL を登録し、接続します。ログインは普段の Web 版と同じアカウントです。

接続先は記憶され、次の起動では自分のグループへ自動接続します。接続先の変更は設定やトレイから行います。複数のグループを同時に使う前提にはしていません。同じインストーラーを配り、各メンバーが自分のグループの URL を使います。

接続設定の「グループ名」は、その端末で接続先を見分けるための表示名です。サーバー側への登録や、Windows のサービス名との一致は不要です。今の1グループを使い続ける場合、既存の `TodoTeamServer` をそのまま使えます。メンバーには今のサーバー URL とアカウントを案内します。

グループ名は、メイン画面のタイトルバー（`HAKOBI — グループ名`）、トレイのメニューとツールチップ、設定の「HAKOBI デスクトップ」、ミニタイマーと進捗入力のヘッダーに表示します。タイトルバーは1.0.3で修正し、サーバーのHTMLタイトルが読み込まれてもグループ名を保持します。

新しい端末では最初に接続設定が開きます。旧版の個人用設定がある端末では、従来どおり個人用で起動します。トレイの「チーム接続 / 個人用モード」から接続設定を開いてください。個人用 DB を消す必要はありません。

起動時にはローカルのスプラッシュを表示し、サーバーが開けない場合は再接続または接続設定へ進めます。個人用を選べば、従来のローカル DB を使うデスクトップ版を利用できます。ブランド変更後もインストーラーの更新用識別子と旧データ保存先を維持します。

### デスクトップ版の配布と更新のお知らせ

1.0.5 から、サーバーがデスクトップ版のインストーラーを配布します。メンバーは `http://<サーバー>:4577/download` のページからダウンロードします。このページはログインなしで開けます。新しい版を公開すると、デスクトップ版の画面にお知らせが出ます。インストールはメンバーが手動で行います。自動更新はありません。

インストーラーの置き場所は、サーバーの配布フォルダです。`TODO_DESKTOP_DIST` で指定し、既定はリポジトリ直下の `dist-desktop/` です。全グループで同じフォルダを共有できます。サーバーが配るのは、配布フォルダの `latest.yml` に書かれたインストーラー1つだけです。`latest.yml` のバージョン・サイズ・sha512 がインストーラーと一致しないと配布しません。ファイルを手でコピーせず、必ず `npm run publish:desktop` で公開してください。

管理者の公開手順:

1. ルートの `package.json` の `version` を上げます（例: `1.0.5`）。
2. `npm run dist` を実行します。`dist/` に `HAKOBI-1.0.5-setup.exe`、`HAKOBI-1.0.5-setup.exe.blockmap`、`latest.yml` ができます。
3. `npm run publish:desktop` を実行します。`dist/` のインストーラーが `latest.yml` と一致し、`package.json` と同じバージョンかを確かめてから、配布フォルダへコピーします。`latest.yml` は最後に置き換えるので、コピー途中のインストーラーは配布されません。
4. 「公開しました: HAKOBI 1.0.5（…）」と表示されたら、ブラウザで `http://<サーバー>:4577/download` を開き、バージョンを確認します。

サーバーの再起動は不要です。サーバーは `latest.yml` とインストーラーの差し替えを検出して読み直します。古いインストーラーは配布フォルダから消しません。公開元と公開先は `--from <フォルダ>` と `--to <フォルダ>` で変えられます。既定の公開先は `server/.env`（`TODO_ENV_FILE` を指定した場合はそのファイル）の `TODO_DESKTOP_DIST` です。バージョンが `package.json` と違うと公開は止まります。`package.json` と違う版を公開するときは、`--expect-version 1.0.5` のように指定します。

配布中と同じバージョンで、中身の違うインストーラーは公開できません。配布中のファイルをその場で書き換えないためです。インストール済みの PC にも新しい版として伝わらないので、作り直したときは `version` を上げてから `npm run dist` を実行します。同じ中身の公開し直しはできます。

#### ビルドする PC とサーバーが別のとき

インストーラーは開発用の PC でビルドし、サーバーから配布できます。サーバーが配るのは配布フォルダの中身だけなので、ビルドした PC からその配布フォルダへ公開します。方法は2つあります。

**方法1: サーバーの共有フォルダへ直接公開する（おすすめ）**

最初に1回だけ準備します。

1. サーバー PC に配布フォルダを作ります（例: `C:\HakobiServer\dist-desktop`）。
2. このフォルダを Windows の共有フォルダにします（例: 共有名 `hakobi-desktop`）。書き込みは管理者だけに許可します。ここに書き込める人は、メンバーの PC に入るインストーラーを差し替えられるためです。
3. サーバーの `server\.env` に `TODO_DESKTOP_DIST=C:\HakobiServer\dist-desktop` を書き、サービスを再起動します。グループごとの env ファイルを使っている場合は、そのすべてに書きます。
4. ビルド PC で `npm --prefix server install` を実行します。公開コマンドが使います。`npm run dev:server` を使っている PC なら済んでいます。
5. ビルド PC の `server\.env` に `TODO_DESKTOP_DIST=\\<サーバー名>\hakobi-desktop` を書きます。これがビルド PC からの公開先になります。

公開するたびに、ビルド PC で次の操作をします。

1. ルートの `package.json` の `version` を上げます。
2. `npm run dist` を実行します。
3. `npm run publish:desktop` を実行します。表示される「公開先:」が `\\<サーバー名>\hakobi-desktop` であることを確かめます。
4. ブラウザで `http://<サーバー>:4577/download` を開き、新しいバージョンになったことを確かめます。

サーバー PC での作業や再起動はいりません。`server\.env` を変えずに1回だけ公開先を変えるときは、`npm run publish:desktop -- --to \\<サーバー名>\hakobi-desktop` と指定します。

**方法2: ファイルを持っていき、サーバーで公開する**

共有フォルダを使えないときの方法です。

1. ビルド PC で `version` を上げて `npm run dist` を実行します。
2. `dist\` にできた `HAKOBI-<バージョン>-setup.exe`、`HAKOBI-<バージョン>-setup.exe.blockmap`、`latest.yml` の3つを、サーバー PC の `dist\` にコピーします。`dist\` は `server\` と同じ階層に作ります（例: `C:\HakobiServer\dist\`）。USB メモリなどで構いません。
3. サーバー PC の `server\` フォルダで `npm run publish:desktop` を実行します。サーバーの `server\.env` の `TODO_DESKTOP_DIST` へ公開されます。グループごとの env ファイルを使っている場合は、`npm run publish:desktop -- --to <配布フォルダ>` と指定します。
4. ブラウザで `http://<サーバー>:4577/download` を開き、新しいバージョンになったことを確かめます。

- サーバー PC の `server\` は 1.0.5 以降のもの（`server\scripts\publish-desktop.ts` があるもの）にしておきます。
- サーバー PC にルートの `package.json` があると、そのバージョンと照合します。古いままだと公開が止まるので、新しいものに置き換えるか、`npm run publish:desktop -- --expect-version 1.0.5` のように指定します。ルートの `package.json` がなければ照合しません。

配布できないときは、管理者でログインして設定の「デスクトップ版（Windows）」を開くと理由が出ます。サーバーのログにも `[desktop]` で始まる行が出ます。理由には配布フォルダのパスが含まれるため、管理者にだけ表示します。設定のこの欄には、メンバーに案内するダウンロードページの URL も出ます。サーバー PC で `http://localhost:4577` から開いた場合は、ほかの PC では使えない URL になるため注意が出ます。メンバーにはサーバーの IP アドレス（例: `http://192.168.1.10:4577/download`）を案内してください。

メンバーに見えるもの:

| 場所 | 表示 |
| --- | --- |
| デスクトップ版のメイン画面 | 新しい版があると、左下に「HAKOBI の新しいバージョン 1.0.5 があります」のカードが出ます。「ダウンロードページを開く」で、いつものブラウザーにダウンロードページが開きます。「後で」を押すと、その版のカードは出なくなります。さらに新しい版を公開すると、また出ます |
| デスクトップ版の設定「HAKOBI デスクトップ」 | 「このPCのバージョン」を表示します。新しい版があれば「新しいバージョン 1.0.5 を配布しています。」と「ダウンロードページを開く」が出ます |
| ブラウザの設定「デスクトップ版（Windows）」 | 配布中なら「タイマーや通知が使えるデスクトップ版を配布しています」と「ダウンロードページを開く」が出ます |
| ブラウザのログイン画面 | 配布中なら「デスクトップ版（Windows）をダウンロード」のリンクが出ます |
| ダウンロードページ | バージョン、サイズ、公開日、SHA-256、接続先URL、ダウンロードボタン、インストールの手順を表示します。接続先URLは、初めて起動したときの接続設定で入力します |

デスクトップ版は、起動時、サーバーへの再接続時、6時間ごとに新しい版を確かめます。お知らせはインストール済みより新しい版のときだけ出ます。1.0.4 以前のアプリは自分のバージョンを画面へ伝えないため、「1.0.4 以前」として扱います。サーバーを 1.0.5 にすれば、1.0.4 以前のアプリにもお知らせが出ます。サーバーが 1.0.4 以前のままなら、お知らせは出ず、ダウンロードページも使えません。

ダウンロードとインストールで出る表示と、進め方:

| 場面 | 表示 | 進め方 |
| --- | --- | --- |
| Chrome でダウンロード | 「安全でないダウンロードがブロックされました」 | ダウンロード一覧を開き、「保存」を選びます |
| Edge でダウンロード | 「安全でないダウンロードがブロックされました」 | 「…」→「保存」を選びます。続けて「一般的にダウンロードされていません」と出たら、「…」（または「詳細表示」）→「保持する」を選びます |
| インストーラーを開く | 「Windows によって PC が保護されました」 | 「詳細情報」を押し、アプリ: `HAKOBI-1.0.5-setup.exe`、発行元: 不明な発行元 であることを確かめて「実行」を押します |
| HAKOBI の起動中にインストール | 「HAKOBI が起動しています。OKをクリックして、閉じてください。」 | OK を押すと HAKOBI が閉じ、インストールが続きます |

- Chrome と Edge のブロックは、サーバーが `http://` で動いているために出ます。LAN の IP アドレスでも同じです。例外は `localhost` だけです。
- 「Windows によって PC が保護されました」は、インストーラーにコード署名がないために出ます。新しい版のたびに出ます。
- 起動中の HAKOBI は OK で閉じられます。先にトレイの「HAKOBIを終了」で終了しておくと、より確実です。終了は必須ではありません。
- 管理者権限は不要です。ユーザーごとのインストールなので、UAC の確認も出ません。データと接続設定はそのまま引き継ぎます。
- スマート アプリ コントロールが有効な PC では、署名のないインストーラーがブロックされ、インストールできません。ダウンロードページでは、管理者へ相談するよう案内しています。
- ダウンロードしたファイルは、PowerShell の `Get-FileHash` で SHA-256 を出し、ダウンロードページの値と照合できます。

社内の IT 管理者が設定できる場合の任意の対策:

- Chrome / Edge のポリシー `InsecureContentAllowedForUrls` に、サーバーのオリジン（例: `http://192.168.1.10:4577`）を登録します。このサーバーからのダウンロードがブロックされなくなります。
- サーバーを Windows の「ローカル イントラネット」ゾーンに登録します。ブラウザーや Windows の警告が減る可能性がありますが、効果は未確認です。

前の版に戻すとき:

- 古いコードから、より高いバージョン番号（例: `1.0.6`）でビルドし、`npm run publish:desktop` で公開します。
- アプリが自動で古い版へ戻ることはありません。インストール済みと同じか低い番号を公開しても、その PC にはお知らせが出ません。
- 公開しても前のインストーラーは配布フォルダに残ります。ダウンロードページで配るのは `latest.yml` に書かれた最新の1つだけです。

自動更新（自動のダウンロードやインストール）は含みません。`electron-builder.yml` の `publish:` は `dist/latest.yml` を作るために残しています。アプリはこの URL へ接続しません。

### Windows のタスクバーに旧アイコンが残る場合

1. トレイから動作中の HAKOBI / ToDo を終了します。旧プロセスが残っていると、新版を起動しても旧ウィンドウが表示されます。
2. 新しいインストーラーで更新するか、新版の `HAKOBI.exe` を起動します。
3. 旧 ToDo をタスクバーに固定している場合は固定を外し、新版を起動して固定し直します。

1.0.3 では、WindowsのタスクバーとショートカットにHAKOBI専用のアプリIDを使い、旧ToDoと同じグループにまとめられないようにします。チーム接続と接続設定のウィンドウには、現在の実行ファイルのアイコンと起動先も明示します。インストーラーの更新用GUID、データと接続設定の保存先、個人用のカスタムアイコンは保持します。この修正ではサーバー更新やサービスの再登録は不要です。

## デスクトップで増える操作

| 操作 | 使い方 |
| --- | --- |
| 右下のミニタイマー | 作業中タスクと経過時間を表示。ウィンドウを移動し、表示や最前面固定を切り替えられます |
| 進捗のクイック投稿 | トレイや `Ctrl+Alt+P` から開き、作業中タスクなどに短い進捗を投稿します |
| 投稿のショートカット | 入力後に `Ctrl+Enter` で投稿します。入力途中の内容は端末に下書きとして保存します |
| トレイ | メイン画面、タイマー、進捗入力、通知、接続設定を開きます。最近計測したタスクを選んで、計測の開始・切り替え・停止もできます |
| 通知 | 担当の追加・返信・メンション・いいね・期限の通知を、OS の通知として表示します。クリックすると、アプリ内の通知一覧で選んだときと同じ画面を開きます |
| 未読バッジ | 未読の通知があると、トレイのアイコンに赤い丸、Windows のタスクバーのアイコンに未読数を表示します |
| タスクバー（Windows） | タスクバーのプレビューに「計測の開始/停止」「進捗をすぐ書く」「タスクを追加」のボタンを表示します。アイコンの右クリック（ジャンプリスト）でもトレイと同じ操作ができます。「計測」の欄に、計測中なら「計測を停止」、最近のタスクの「計測開始（計測中は切り替え）」を出し、「タスク」の欄から、メイン画面・通知（未読数つき）・タスク追加・進捗入力・タイマー表示・接続先の変更・終了を選べます |
| メイン画面の呼び出し | `Ctrl+Alt+T` で前面表示します |

タイマーの開始・停止と記録はサーバーが管理します。経過時間の表示は端末で進めるため、サーバーへ毎秒通信しません。別の端末で変更された作業状態はサーバーの同期で反映されます。ウィジェットを閉じても、計測を止める操作をしない限りタイマーは継続します。

1.0.4では、タイマーの枠をドラッグして大きさを変更できます。コンパクト表示は初期サイズ320×150、通常表示は360×250で、それぞれ変更した大きさを端末に保存します。表示モードも再起動後に復元します。コンパクトでも作業中のタスク名、経過時間、進捗入力ボタン、停止ボタンを表示します。「タイマーにタスク名を表示しない」を選んだ場合は、どちらのモードでも名前を隠します。

### 通知とタスクバー

OS の通知は、サーバーで新しく作られた未読の通知だけを表示します。最初の起動では、それまでの通知を一度に出さずに記録だけします。スリープ中などにまとめて届いた場合は、4件以上を「新しい通知が◯件あります」の1件にまとめ、クリックで通知一覧を開きます。メイン画面を前面で見ているときは、アプリ内のベルで分かるので OS の通知を出しません。通知の表示は、トレイまたは設定の「通知をデスクトップに表示」で端末ごとに切り替えます。通知の種類ごとのオン・オフは、従来どおりアプリ内の通知設定で行います。

トレイとタスクバーに出すタスクは、自分が最近14日以内に計測したタスク（新しい順）と、自分が担当する進行中のタスク（期限の近い順）から最大5件です。保留中・完了・計測中のタスクは出しません。計測の開始・停止はサーバーで行い、失敗したときは理由をダイアログで表示します。停止はトレイに表示していた計測だけを止めるので、別の端末で切り替えた計測を誤って止めません。

サーバーの画面とデスクトップ版は別々に更新できます。サーバーだけが古い場合はトレイの計測切り替えと通知が出ず、デスクトップ版だけが古い場合はサーバーの画面がこれらの機能を使いません。どちらの組み合わせでも従来の操作はそのまま使えます。

ガントは、タスクの期間を伸ばす・同期で更新する・ウィンドウ幅を変える・ズームを変える操作で、見ている日付を保持します。今日へ移動するのは初回表示と「今日に戻る」を押したときです。

メイン画面・右下タイマー・トレイの経過時間はサーバー時刻に合わせます。端末の時計がずれていても、同じ作業の時間を揃えて表示します。サーバーへの保存は従来どおりサーバー時刻で行います。

クイック投稿の「保存した下書き」から、未投稿・送信結果未確認・削除済みタスクの文章を開けます。本文のコピーや、未送信の文章を別タスクへ移す操作もできます。送信結果が未確認の場合は、同じ投稿を再試行して結果を確認してください。結果が分かるまで投稿先と文章の移し替えを止め、二重投稿を防ぎます。

更新前のWeb版の文章は、設定の「旧版の下書きを確認・復元」から選択して回復できます。保存したブラウザと接続URLで操作し、自分が書いたものだけを選んでください。現在の下書きは上書きしません。ブラウザとElectronの保存領域は別なので、ブラウザの書きかけの文章は必要に応じてコピーしてElectronへ移します。投稿済みの進捗はサーバーDBにあります。

ショートカットをOSや別アプリへ登録できない場合は、日本語で失敗を表示します。設定変更に失敗したら元の設定へ戻ります。起動時の一部のキーの競合で、ほかの使えるキーまで無効にはしません。

接続先やウィンドウ設定は端末側に保存します。グループの共有設定や他のメンバーの画面配置を変更しません。ログインセッションは接続先ごとの Electron の保存領域で分けます。

## グループごとにサーバーと DB を分ける

グループごとにサーバープロセスを立て、`PORT` と `TODO_DATA_DIR` を変えます。DB・アカウント・作業記録・添付データは指定したデータフォルダごとに独立します。ポート番号を変えるだけでは DB は分かれません。

| グループ | 接続 URL | データ保存先 | Cookie 名 | サービス名 |
| --- | --- | --- | --- | --- |
| A | `http://192.168.1.10:4577` | `C:\HakobiData\group-a` | `hakobi_group_a` | `HakobiGroupA` |
| B | `http://192.168.1.10:4578` | `C:\HakobiData\group-b` | `hakobi_group_b` | `HakobiGroupB` |

ブラウザの Cookie はポート別には分離されません。同じホストの別ポートを使う場合は、サーバーごとに `SESSION_COOKIE` を変えます。Cookie 名の違いだけをアクセス制御に使うことはできません。各サーバーがログインを検証します。デスクトップ版はこれに加え、接続先ごとにセッションの保存領域を分けます。

`C:\HakobiServer\groups\group-a.env` の例:

```dotenv
PORT=4577
TODO_DATA_DIR=C:\HakobiData\group-a
TODO_WEB_DIST=C:\HakobiServer\dist-web
TODO_DESKTOP_DIST=C:\HakobiServer\dist-desktop
SESSION_COOKIE=hakobi_group_a
TODO_SERVICE_NAME=HakobiGroupA
TODO_SERVICE_DESCRIPTION=HAKOBI Aグループ
ADMIN_USERNAME=admin
```

B グループ用には別ファイルを作り、ポート、データフォルダ、Cookie 名、サービス名を変更します。`TODO_DESKTOP_DIST` は全グループで同じフォルダを指定できます。一度公開すれば、全グループのメンバーが同じインストーラーをダウンロードできます。初期パスワードを指定する場合は `ADMIN_PASSWORD` を設定します。未指定では初回起動ログに生成されたパスワードが表示されます。

PowerShell でグループ A を起動する例:

```powershell
$env:TODO_ENV_FILE='C:\HakobiServer\groups\group-a.env'
npm run start:server
```

`TODO_ENV_FILE` が指定されているのにファイルが存在しない場合は、既定の DB に接続せずエラーで止まります。設定ファイルよりシェルの環境変数が優先されるため、別グループの `PORT` や `TODO_DATA_DIR` を残さないでください。

## 複数の Windows サービス

管理者として開いた PowerShell から、グループごとに設定ファイルを選んで登録します。次のコマンドはサービスの登録と起動を行います。

```powershell
$env:TODO_ENV_FILE='C:\HakobiServer\groups\group-a.env'
npm run service:install

$env:TODO_ENV_FILE='C:\HakobiServer\groups\group-b.env'
npm run service:install
```

独自名のサービスでは `PORT` と `TODO_DATA_DIR` が必須です。サービス名は英字で始まる英数字・アンダースコア、64 文字以内で指定します。ラッパーは `server/service/instances/<サービス名の小文字>/daemon/`、ログはその隣の `logs/` に分離します。既定名 `TodoTeamServer` は旧版との互換性のため維持し、既存の `server/service/daemon/` を使います。

`TODO_ENV_FILE` はサービスに絶対パスで渡します。ファイル内のサーバー設定を変えたらサービスを再起動します。シェルで指定してから登録した環境変数はサービスに固定され、ファイルの値より優先されます。その値を変える場合は登録し直します。サービス名の変更でも再登録が必要です。

グループ B のサービスを解除する例:

```powershell
$env:TODO_ENV_FILE='C:\HakobiServer\groups\group-b.env'
npm run service:uninstall
```

サービス解除では DB を削除しません。既存の `TodoTeamServer` を解除する際は、独自の `TODO_SERVICE_NAME` と `TODO_ENV_FILE` が指定されていないことを確認します。

## 更新とバックアップ

- サーバーコードと Web ビルドを一組として更新し、ブラウザとデスクトップの両方でログイン・タスク保存・同期を確認します。
- デスクトップのネイティブ機能を変更した場合は、`package.json` の `version` を上げて `npm run dist` を実行し、`npm run publish:desktop` で公開します。メンバーにはアプリのお知らせで伝わるので、インストーラーを個別に配る必要はありません。Web 画面だけの変更では、サーバーの更新後に画面を再読み込みします。
- 配布フォルダ（既定 `dist-desktop/`、`TODO_DESKTOP_DIST` 設定時はその場所）は、`dist-web/` を置き換えるときも残します。DB ではないのでバックアップは必須ではありません。消えた場合は `npm run publish:desktop` で公開し直します。
- グループごとのデータフォルダをバックアップします。SQLite の WAL を使うため、運用中に `todo.db` だけをコピーする方法は避けます。サーバー停止後にデータフォルダ全体をコピーするか、SQLite のバックアップ機能を使います（下の自動バックアップと、設定画面のダウンロードはこの機能を使っています）。
- 旧版で保存先を変更していた個人用データは、その保存先を保持します。チームの DB への自動移行は行いません。

### 自動バックアップ

サーバーは起動時と1分ごとの点検で、その日のバックアップがなければ取ります（1日1つ、`hakobi-YYYY-MM-DD.db`）。既定ではデータフォルダの `backups/` に置き、14日分を残して古いものから消します。ほかのファイルは消しません。

| 設定 | 既定 | 内容 |
| --- | --- | --- |
| `TODO_BACKUP_DIR` | `<TODO_DATA_DIR>\backups` | 自動バックアップの置き場所。別のドライブにすると、ディスクの故障にも備えられます |
| `TODO_BACKUP_KEEP` | `14` | 残す数（日数）。`0` で自動バックアップを止めます |

管理者は、設定画面の「チーム管理」→「バックアップ」から今のデータを1つのファイル（`hakobi-backup-YYYYMMDD-HHmm.db`）でダウンロードできます。自動バックアップの最新の日時と置き場所もそこで確かめられます。バックアップは1つのファイルだけで開けます（`-wal`・`-shm` は要りません）。

### バックアップから戻す

画面からは戻しません。サーバーで次の順に行います。

1. サーバー（Windows サービス）を止めます。
2. データフォルダの `todo.db`・`todo.db-wal`・`todo.db-shm` を別の場所へ移します（戻した結果がおかしかったときに使います）。
3. 戻したいバックアップ（`backups\hakobi-YYYY-MM-DD.db` やダウンロードしたファイル）を、データフォルダへ `todo.db` という名前でコピーします。
4. サーバーを起動し、ブラウザで開き直して、タスクとアカウントを確かめます。

バックアップを取ったあとの変更（タスク・進捗ログ・作業記録など）は消えます。ログインのセッションもバックアップの時点に戻るので、ログインし直しが必要な人がいます。

## 利用範囲

社内 LAN と常時オンラインでの利用を前提とします。サーバーへ接続できない間は、タスクや進捗をサーバーに保存できません。進捗の下書きを端末に残し、再接続してから投稿できます。アプリ全体のオフライン編集・自動同期、インターネット公開、複数グループの同時利用は今回の実装には含みません。デスクトップ版はサーバーからダウンロードでき、新しい版があるとお知らせを出します。自動更新（自動のダウンロードやインストール）は含みません。インストールはメンバーが手動で行います。

## 開発時の確認

`npm run build` と `npm run build:web` の後に `npm run test:quality` と `npm run test:hakobi` を実行します。保存先変更・削除・依存関係・同時編集・取り込みを確認し、実際の Electron でログイン、タイマー、下書き、進捗投稿、通信失敗からの再試行、同期も確認します。テストは独立した一時 DB と保存領域を使い、運用中の DB や Windows サービスを変更しません。

`npm run dist` の後に `node tests/hakobi-package.cjs` を実行すると、配布物に必要なクライアントファイルがあり、サーバーの設定や DB が含まれていないことを確認できます。

Windowsではインストーラー作成後に `npm run test:installer` を実行すると、同名ショートカットの更新処理を実NSISとWinShellで確認できます。リンクは専用の一時フォルダに作成し、実ユーザーのスタートメニューやデスクトップは変更しません。

`npm run test:gantt-scroll` は、実Reactと非表示Electronで期間バーの伸縮、同期中、幅変更、ズーム、保存したスクロール位置の復元を確認します。

障害条件を含む確認結果は[2026年10月9日の修正結果](./HAKOBI_REVIEW_2026-10-09.md)にまとめています。

その後の全体確認と追加修正は[全体確認・修正結果](./HAKOBI_FULL_REVIEW_2026-10-09.md)にまとめています。1.0.4 までは、サーバー本体の `server/` は1.0.1を継続できました。タイマーとガントの修正を使うには、配布用インストーラーとサーバーが配信するWeb画面を1.0.4へ更新してください。1.0.5 のダウンロードと更新のお知らせを使うには、`server/` の更新も必要です（下記）。チーム利用は既存のサーバーDBを継続して使うため、個人DBの取り込みは不要です。

1.0.4 の作成済みファイルは `dist/HAKOBI-1.0.4-setup.exe` と `dist/HAKOBI-web-1.0.4.zip` です。WebのZIPは展開した `index.html` と `assets/` を、サーバーが使っている `dist-web/`（`TODO_WEB_DIST` のフォルダ）へ配置します。DB・アカウント・設定ファイルは変更せず、画面を再読み込みしてください。検証用Webビルドは `dist/1.0.4/web/` に作成し、稼働中の `dist-web/` は自動で置き換えていません。

1.0.5 では、デスクトップ版のダウンロードと更新のお知らせを追加しました。`npm run dist` で `dist/HAKOBI-1.0.5-setup.exe`、`dist/HAKOBI-1.0.5-setup.exe.blockmap`、`dist/latest.yml` を作成します。メンバーへはファイルを直接配らず、`npm run publish:desktop` でサーバーの配布フォルダへ公開します。この機能を使うには、`server/`（`server/src/`、`server/scripts/`、`server/package.json`）とサーバーが配信するWeb画面も1.0.5へ更新し、サーバーを再起動します。サーバーの依存パッケージと DB は変わりません。
