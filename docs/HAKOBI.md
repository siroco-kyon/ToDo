# HAKOBI のチーム接続と運用

HAKOBI のデスクトップ版は、サーバーが配信する Web 画面を Electron のウィンドウに表示します。画面と API はサーバー側で更新し、タイマーやトレイなどの端末機能はデスクトップ版が担当します。タスクと進捗の保存先は既存のサーバー DB です。

## メンバーへの配布

1. サーバーで `npm run build:web` を実行し、`dist-web/` と更新した `server/` を配置します。
2. サーバーを起動し、同じ LAN の端末から `http://<サーバーIP>:4577` を開けることを確認します。
3. 管理者がメンバーのアカウントを発行します。
4. `npm run dist` で作成した `dist/HAKOBI-1.0.4-setup.exe` をメンバーへ配布します。
5. HAKOBI の接続設定でグループ名とサーバー URL を登録し、接続します。ログインは普段の Web 版と同じアカウントです。

接続先は記憶され、次の起動では自分のグループへ自動接続します。接続先の変更は設定やトレイから行います。複数のグループを同時に使う前提にはしていません。同じインストーラーを配り、各メンバーが自分のグループの URL を使います。

接続設定の「グループ名」は、その端末で接続先を見分けるための表示名です。サーバー側への登録や、Windows のサービス名との一致は不要です。今の1グループを使い続ける場合、既存の `TodoTeamServer` をそのまま使えます。メンバーには今のサーバー URL とアカウントを案内します。

グループ名は、メイン画面のタイトルバー（`HAKOBI — グループ名`）、トレイのメニューとツールチップ、設定の「HAKOBI デスクトップ」、ミニタイマーと進捗入力のヘッダーに表示します。タイトルバーは1.0.3で修正し、サーバーのHTMLタイトルが読み込まれてもグループ名を保持します。

新しい端末では最初に接続設定が開きます。旧版の個人用設定がある端末では、従来どおり個人用で起動します。トレイの「チーム接続 / 個人用モード」から接続設定を開いてください。個人用 DB を消す必要はありません。

起動時にはローカルのスプラッシュを表示し、サーバーが開けない場合は再接続または接続設定へ進めます。個人用を選べば、従来のローカル DB を使うデスクトップ版を利用できます。ブランド変更後もインストーラーの更新用識別子と旧データ保存先を維持します。

### Windows のタスクバーに旧アイコンが残る場合

1. トレイから動作中の HAKOBI / ToDo を終了します。旧プロセスが残っていると、新版を起動しても旧ウィンドウが表示されます。
2. 新しいインストーラーで更新するか、新版の `HAKOBI.exe` を起動します。
3. 旧 ToDo をタスクバーに固定している場合は固定を外し、新版を起動して固定し直します。

1.0.3 では、WindowsのタスクバーとショートカットにHAKOBI専用のアプリIDを使い、旧ToDoと同じグループにまとめられないようにします。チーム接続と接続設定のウィンドウには、現在の実行ファイルのアイコンと起動先も明示します。インストーラーの更新用GUID、データと接続設定の保存先、個人用のカスタムアイコンは保持します。この修正ではサーバー更新やサービスの再登録は不要です。

## デスクトップで増える操作

| 操作 | 使い方 |
| --- | --- |
| 右下のミニタイマー | 作業中タスクと経過時間を表示。ウィンドウを移動し、表示や最前面固定を切り替えられます |
| 進捗のクイック投稿 | トレイや `Ctrl+Alt+P` から開き、作業中タスクなどに短い進捗を投稿します |
| 投稿のショートカット | 入力後に `Ctrl+Enter` で投稿します。入力途中の内容は端末に下書きとして保存します |
| トレイ | メイン画面、タイマー、進捗入力、接続設定を開きます |
| メイン画面の呼び出し | `Ctrl+Alt+T` で前面表示します |

タイマーの開始・停止と記録はサーバーが管理します。経過時間の表示は端末で進めるため、サーバーへ毎秒通信しません。別の端末で変更された作業状態はサーバーの同期で反映されます。ウィジェットを閉じても、計測を止める操作をしない限りタイマーは継続します。

1.0.4では、タイマーの枠をドラッグして大きさを変更できます。コンパクト表示は初期サイズ320×150、通常表示は360×250で、それぞれ変更した大きさを端末に保存します。表示モードも再起動後に復元します。コンパクトでも作業中のタスク名、経過時間、進捗入力ボタンを表示します。「タイマーにタスク名を表示しない」を選んだ場合は、どちらのモードでも名前を隠します。

ガントは、タスクの期間を伸ばす・同期で更新する・ウィンドウ幅を変える・ズームを変える操作で、見ている日付を保持します。今日へ移動するのは初回表示と「今日に戻る」を押したときです。

メイン画面・右下タイマー・トレイの経過時間はサーバー時刻に合わせます。端末の時計がずれていても、同じ作業の時間を揃えて表示します。サーバーへの保存は従来どおりサーバー時刻で行います。

クイック投稿の「保存した下書き」から、未投稿・送信結果未確認・削除済みタスクの文章を開けます。本文のコピーや、未送信の文章を別タスクへ移す操作もできます。送信結果が未確認の場合は、同じ投稿を再試行して結果を確認してください。結果が分かるまで投稿先と文章の移し替えを止め、二重投稿を防ぎます。

更新前のWeb版の文章は、設定の「旧版の下書きを確認・復元」から選択して回復できます。保存したブラウザと接続URLで操作し、自分が書いたものだけを選んでください。現在の下書きは上書きしません。ブラウザとElectronの保存領域は別なので、ブラウザの書きかけの文章は必要に応じてコピーしてElectronへ移します。投稿済みの進捗はサーバーDBにあります。

ショートカットをOSや別アプリへ登録できない場合は、日本語で失敗を表示します。設定変更に失敗したら元の設定へ戻ります。起動時の一部のキーの競合で、ほかの使えるキーまで無効にはしません。

接続先やウィンドウ設定は端末側に保存します。グループの共有設定や他のメンバーの画面配置を変更しません。ログインセッションは接続先ごとの Electron の保存領域で分けます。

## グループごとにサーバーと DB を分ける

グループごとにサーバープロセスを立て、`PORT` と `TODO_DATA_DIR` を変えます。DB・アカウント・作業記録・添付データは指定したデータフォルダごとに独立します。ポート番号を変えるだけでは DB は分かれません。

| グループ | 接続 URL | データ保存先 | Cookie 名 | サービス名 |
| --- | --- | --- | --- | --- |
| A | `http://192.168.1.10:4577` | `C:\HakobiData\group-a` | `hakobi_group_a` | `HakobiGroupA` |
| B | `http://192.168.1.10:4578` | `C:\HakobiData\group-b` | `hakobi_group_b` | `HakobiGroupB` |

ブラウザの Cookie はポート別には分離されません。同じホストの別ポートを使う場合は、サーバーごとに `SESSION_COOKIE` を変えます。Cookie 名の違いだけをアクセス制御に使うことはできません。各サーバーがログインを検証します。デスクトップ版はこれに加え、接続先ごとにセッションの保存領域を分けます。

`C:\HakobiServer\groups\group-a.env` の例:

```dotenv
PORT=4577
TODO_DATA_DIR=C:\HakobiData\group-a
TODO_WEB_DIST=C:\HakobiServer\dist-web
SESSION_COOKIE=hakobi_group_a
TODO_SERVICE_NAME=HakobiGroupA
TODO_SERVICE_DESCRIPTION=HAKOBI Aグループ
ADMIN_USERNAME=admin
```

B グループ用には別ファイルを作り、ポート、データフォルダ、Cookie 名、サービス名を変更します。初期パスワードを指定する場合は `ADMIN_PASSWORD` を設定します。未指定では初回起動ログに生成されたパスワードが表示されます。

PowerShell でグループ A を起動する例:

```powershell
$env:TODO_ENV_FILE='C:\HakobiServer\groups\group-a.env'
npm run start:server
```

`TODO_ENV_FILE` が指定されているのにファイルが存在しない場合は、既定の DB に接続せずエラーで止まります。設定ファイルよりシェルの環境変数が優先されるため、別グループの `PORT` や `TODO_DATA_DIR` を残さないでください。

## 複数の Windows サービス

管理者として開いた PowerShell から、グループごとに設定ファイルを選んで登録します。次のコマンドはサービスの登録と起動を行います。

```powershell
$env:TODO_ENV_FILE='C:\HakobiServer\groups\group-a.env'
npm run service:install

$env:TODO_ENV_FILE='C:\HakobiServer\groups\group-b.env'
npm run service:install
```

独自名のサービスでは `PORT` と `TODO_DATA_DIR` が必須です。サービス名は英字で始まる英数字・アンダースコア、64 文字以内で指定します。ラッパーは `server/service/instances/<サービス名の小文字>/daemon/`、ログはその隣の `logs/` に分離します。既定名 `TodoTeamServer` は旧版との互換性のため維持し、既存の `server/service/daemon/` を使います。

`TODO_ENV_FILE` はサービスに絶対パスで渡します。ファイル内のサーバー設定を変えたらサービスを再起動します。シェルで指定してから登録した環境変数はサービスに固定され、ファイルの値より優先されます。その値を変える場合は登録し直します。サービス名の変更でも再登録が必要です。

グループ B のサービスを解除する例:

```powershell
$env:TODO_ENV_FILE='C:\HakobiServer\groups\group-b.env'
npm run service:uninstall
```

サービス解除では DB を削除しません。既存の `TodoTeamServer` を解除する際は、独自の `TODO_SERVICE_NAME` と `TODO_ENV_FILE` が指定されていないことを確認します。

## 更新とバックアップ

- サーバーコードと Web ビルドを一組として更新し、ブラウザとデスクトップの両方でログイン・タスク保存・同期を確認します。
- デスクトップのネイティブ機能を変更した場合は、新しいインストーラーも配布します。Web 画面だけの変更では、サーバーの更新後に画面を再読み込みします。
- グループごとのデータフォルダをバックアップします。SQLite の WAL を使うため、運用中に `todo.db` だけをコピーする方法は避けます。サーバー停止後にデータフォルダ全体をコピーするか、SQLite のバックアップ機能を使います。
- 旧版で保存先を変更していた個人用データは、その保存先を保持します。チームの DB への自動移行は行いません。

## 利用範囲

社内 LAN と常時オンラインでの利用を前提とします。サーバーへ接続できない間は、タスクや進捗をサーバーに保存できません。進捗の下書きを端末に残し、再接続してから投稿できます。アプリ全体のオフライン編集・自動同期、インターネット公開、複数グループの同時利用、自動更新の配信は今回の実装には含みません。

## 開発時の確認

`npm run build` と `npm run build:web` の後に `npm run test:quality` と `npm run test:hakobi` を実行します。保存先変更・削除・依存関係・同時編集・取り込みを確認し、実際の Electron でログイン、タイマー、下書き、進捗投稿、通信失敗からの再試行、同期も確認します。テストは独立した一時 DB と保存領域を使い、運用中の DB や Windows サービスを変更しません。

`npm run dist` の後に `node tests/hakobi-package.cjs` を実行すると、配布物に必要なクライアントファイルがあり、サーバーの設定や DB が含まれていないことを確認できます。

Windowsではインストーラー作成後に `npm run test:installer` を実行すると、同名ショートカットの更新処理を実NSISとWinShellで確認できます。リンクは専用の一時フォルダに作成し、実ユーザーのスタートメニューやデスクトップは変更しません。

`npm run test:gantt-scroll` は、実Reactと非表示Electronで期間バーの伸縮、同期中、幅変更、ズーム、保存したスクロール位置の復元を確認します。

障害条件を含む確認結果は[2026年10月9日の修正結果](./HAKOBI_REVIEW_2026-10-09.md)にまとめています。

その後の全体確認と追加修正は[全体確認・修正結果](./HAKOBI_FULL_REVIEW_2026-10-09.md)にまとめています。サーバー本体の `server/` は1.0.1を継続できます。タイマーとガントの修正を使うには、配布用インストーラーとサーバーが配信するWeb画面を1.0.4へ更新してください。チーム利用は既存のサーバーDBを継続して使うため、個人DBの取り込みは不要です。

今回の作成済みファイルは `dist/HAKOBI-1.0.4-setup.exe` と `dist/HAKOBI-web-1.0.4.zip` です。WebのZIPは展開した `index.html` と `assets/` を、サーバーが使っている `dist-web/`（`TODO_WEB_DIST` のフォルダ）へ配置します。DB・アカウント・設定ファイルは変更せず、画面を再読み込みしてください。検証用Webビルドは `dist/1.0.4/web/` に作成し、稼働中の `dist-web/` は自動で置き換えていません。
